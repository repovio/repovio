<a id="review-accounts"></a>

## مراجعة الحسابات

يفتح مسؤولو النظام **الإدارة → المستخدمين**. يعرض الجدول اسم المستخدم، والصورة الرمزية/اسم العرض، والدور، والأصل
المحلي/OIDC، والطوابع الزمنية التي تم إنشاؤها/تحديثها. قم بالتصفية حسب الدور أو الفرز أو تغيير الأعمدة أو ترقيم الصفحات.
يتطلب الوصول إلى المستودع للعارض أو المدير [عضوية المستودع](/docs/v2.0/repositories) منفصلاً؛ لا تقوم مجموعات موفري
الهوية بإنشاء تلك العضويات.

<a id="provisioning-and-deletion"></a>

## التزويد والحذف

من الإدارة ← المستخدمون اختر مستخدماً جديداً في شريط الأدوات. أدخل اسماً فريداً واسمين اختياريين وكلمة مرور من 12–256
حرفاً وتأكيدها ودوراً؛ الافتراضي Viewer. الإنشاء متاح مع OIDC أيضاً. هويات OIDC تُنشأ لدى المزود ولا تُربط بتطابق اسم
محلي.

إجراء الحذف متاح للمستخدمين الآخرين ويتم تنفيذه على الفور؛ قم بمراجعة الحساب قبل اختياره. لا يمكنك حذف حسابك الخاص من
خلال واجهة برمجة التطبيقات هذه أو الشاشة. يؤدي حذف مستخدم Repovio إلى إزالة الوصول المحلي؛ ولا يحذف أي حساب موفر على
GitHub أو GitLab أو Forgejo أو Gitea. قم بمراجعة وصول المستخدم المتأثر قبل الحذف.

<a id="user-mcp-tokens"></a>

## الرموز المميزة للمستخدم MCP

افتح مربع حوار الرمز المميز MCP الخاص بالمستخدم لسرد بيانات تعريف الرمز المميز أو إلغاء الرمز المميز مع التأكيد. لا يمكن
للمسؤولين استرداد قيم الرمز المميز للنص العادي أو إنشاء رمز مميز لمستخدم آخر من خلال مربع الحوار هذا. يقوم المستخدمون
بإنشاء الرموز المميزة الخاصة بهم في [إعدادات MCP](/docs/v2.0/mcp). تختلف القوائم الفارغة عن أخطاء التحميل؛ أعد المحاولة
بعد استرداد API. لا تقم مطلقًا بنسخ قيم الرموز المميزة في تقارير الدعم أو لقطات الشاشة.

<a id="local-user-api"></a>

## توفير مستخدم محلي من خلال واجهة برمجة التطبيقات

استخدم عميل API عبر HTTPS لإرسال `POST /api/v1/users` مع مصادقة حامل المسؤول و`Content-Type: application/json`. قم
بتوفير نص الطلب هذا، مع استبدال العناصر النائبة في المدخلات المحمية للعميل:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

الأدوار الصالحة هي `VIEWER`، و`MANAGER`، و`SYSTEM_ADMIN`. قم بتعيين الدور المطلوب فقط، ثم قم بمنح عضويات المستودع بشكل
منفصل. تحتوي الاستجابة على بيانات تعريف آمنة للمستخدم، وليس كلمة المرور أو التجزئة الخاصة بها. يجب تصحيح اسم المستخدم
المكرر أو الطلب غير الصالح قبل إعادة المحاولة. لا تقم بتخزين كلمات المرور أو الرموز المميزة لحاملها في الملفات المتعقبة
أو سجل الصدفة أو لقطات الشاشة أو تقارير الإصدار.

<a id="create-and-reset-local-accounts"></a>

## إنشاء الحسابات المحلية وإعادة تعيينها

إجراء إعادة تعيين كلمة المرور في صف حساب محلي يسمح للمسؤول بتعيين بديل دون القديمة. أدخل الجديدة وتأكيدها. تصبح جلسات
JWT السابقة غير صالحة؛ إعادة تعيين حسابك تسجل خروجك. لا يظهر الإجراء لحسابات OIDC. رموز MCP لا تُلغى.

<a id="local-access-groups"></a>

## مجموعات الوصول المحلية

افتح الإدارة ← مجموعات المستخدمين لإنشاء مجموعة وتغيير اسمها وحذفها وإدارة الأعضاء. الأسماء فريدة وغير فارغة. يدعم
الاختيار البحث والصفحات ويمكن للمستخدم الانضمام إلى عدة مجموعات دون تداخل. الحذف يحتاج تأكيداً ويزيل العضويات والصلاحيات
الموروثة مع الحفاظ على التعيينات المباشرة.

في وصول المجموعات للمستودع عيّن Viewer أو Manager أو غيّر الصلاحية أو احذفها. تُجمع الصلاحيات المباشرة والموروثة وتغلب
Manager. تتطلب الإدارة دور Manager عاماً أيضاً؛ مسؤول النظام غير مقيد. يسري الإلغاء في الطلب التالي ما لم تبق صلاحية
أخرى. تدعم المجموعات الحسابات المحلية وOIDC دون مزامنة مطالبات OIDC.

```text
POST   /api/v1/users                              { username, password, role, firstName?, lastName? }
PUT    /api/v1/users/:id/password                 { newPassword }
GET    /api/v1/user-groups                       ?page=1&perPage=10
POST   /api/v1/user-groups                       { name }
PUT    /api/v1/user-groups/:id                    { name }
DELETE /api/v1/user-groups/:id
GET    /api/v1/user-groups/:id/members            ?page=1&perPage=10
PUT    /api/v1/user-groups/:id/members/:userId
DELETE /api/v1/user-groups/:id/members/:userId
GET    /api/v1/repositories/:id/group-memberships
PUT    /api/v1/repositories/:id/group-memberships/:groupId  { role }
DELETE /api/v1/repositories/:id/group-memberships/:groupId
```
