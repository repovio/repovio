<a id="server-requirements"></a>

## サーバー要件

ブラウザ プッシュはネイティブ トランスポートであり、 Apprise。導入オペレータは、次の 3 つの設定をすべて構成します。

```dotenv
WEB_PUSH_VAPID_PUBLIC_KEY=...
WEB_PUSH_VAPID_PRIVATE_KEY=...
WEB_PUSH_VAPID_SUBJECT=mailto:admin@example.com
```

VAPID キー ペアを生成します。 `npx web-push generate-vapid-keys`。主題は `mailto:` または `https:`
URI。秘密鍵は秘密にしておきます。完全な構成がないと、ブラウザーのプッシュは利用できないと表示されます。安全なブラウザ コンテキストと、Service
Worker および Push API をサポートするブラウザを使用します。

<a id="enable-or-disable-this-device"></a>

## このデバイスを有効または無効にします

[**このデバイスで有効にする**] を使用し、要求に応じてブラウザーの通知権限を付与します。サブスクリプションは現在のユーザーとブラウザーに属します。管理者はブラウザ プッシュ チャネルで受信者ユーザーを選択します。各受信者には有効なデバイスが必要です。ブラウザの許可を拒否すると、購読できなくなります。サイトのブラウザ許可を調整し、必要に応じて再試行してください。テストを送信する前に、可用性/デバイス数と報告されたエラーを確認してください。

プッシュを無効にすると、他のデバイスではなく、このデバイスのサブスクリプションが削除されます。エンドポイントとキーは暗号化され、非機密フィンガープリントで重複排除されます。 HTTP
404/410 応答により、期限切れのサブスクリプションが削除されます。ブラウザーが使用できない、サーバー構成が欠落している、権限が拒否されている、またはサブスクリプション要求が失敗している場合は、対応する原因を修正する必要があります。更新だけではブラウザに許可を与えることはできません。見る
[配信履歴](/docs/v1.0/notification-history) 試みのために。
