<a id="review-accounts"></a>

## खातों की समीक्षा करें

सिस्टम प्रशासक **प्रशासन → उपयोगकर्ता** खोलते हैं। तालिका उपयोगकर्ता नाम, अवतार/प्रदर्शन नाम, भूमिका, स्थानीय/OIDC मूल,
और निर्मित/अद्यतन टाइमस्टैम्प दिखाती है। भूमिका के आधार पर फ़िल्टर करें, क्रमबद्ध करें, कॉलम बदलें या पेजिनेट करें। किसी
दर्शक या प्रबंधक के लिए रिपॉजिटरी एक्सेस के लिए एक अलग [भंडार सदस्यता](/docs/v2.0/repositories) की आवश्यकता होती है;
पहचान-प्रदाता समूह वे सदस्यताएँ नहीं बनाते हैं।

<a id="provisioning-and-deletion"></a>

## प्रावधान करना और हटाना

प्रशासन → उपयोगकर्ता में टूलबार से नया उपयोगकर्ता चुनें। अद्वितीय नाम, वैकल्पिक प्रथम/अंतिम नाम, 12–256 अक्षर का पासवर्ड
व पुष्टि और भूमिका दें; प्रारंभिक भूमिका Viewer है। OIDC चालू होने पर भी निर्माण उपलब्ध है। OIDC पहचान प्रदाता से आती
है; समान स्थानीय नाम से नहीं जुड़ती।

डिलीट कार्रवाई अन्य उपयोगकर्ताओं के लिए उपलब्ध है और तुरंत निष्पादित होती है; खाते को चुनने से पहले उसकी समीक्षा करें.
आप इस एपीआई या स्क्रीन के माध्यम से अपना खाता नहीं हटा सकते। Repovio उपयोगकर्ता को हटाने से स्थानीय पहुंच समाप्त हो जाती
है; यह GitHub, GitLab, Forgejo, या Gitea पर किसी भी प्रदाता खाते को नहीं हटाता है। हटाने से पहले प्रभावित उपयोगकर्ता की
पहुंच की समीक्षा करें।

<a id="user-mcp-tokens"></a>

## उपयोगकर्ता MCP टोकन

टोकन मेटाडेटा को सूचीबद्ध करने या पुष्टि के साथ टोकन को रद्द करने के लिए उपयोगकर्ता का MCP-टोकन संवाद खोलें। व्यवस्थापक
इस संवाद के माध्यम से प्लेनटेक्स्ट टोकन मान पुनर्प्राप्त नहीं कर सकते हैं या किसी अन्य उपयोगकर्ता का टोकन नहीं बना सकते
हैं। उपयोगकर्ता [MCP सेटिंग्स](/docs/v2.0/mcp) में अपने स्वयं के टोकन बनाते हैं। खाली सूचियाँ और लोड त्रुटियाँ अलग-अलग
हैं; एपीआई पुनर्प्राप्ति के बाद पुनः प्रयास करें। कभी भी टोकन मानों को समर्थन रिपोर्ट या स्क्रीनशॉट में कॉपी न करें।

<a id="local-user-api"></a>

## एपीआई के माध्यम से एक स्थानीय उपयोगकर्ता प्रदान करें

प्रशासक वाहक प्रमाणीकरण और `Content-Type: application/json` के साथ `POST /api/v1/users` भेजने के लिए HTTPS पर एपीआई
क्लाइंट का उपयोग करें। क्लाइंट के संरक्षित इनपुट में प्लेसहोल्डर्स को प्रतिस्थापित करते हुए, इस अनुरोध निकाय की आपूर्ति
करें:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

मान्य भूमिकाएँ `VIEWER`, `MANAGER`, और `SYSTEM_ADMIN` हैं। केवल आवश्यक भूमिका निर्दिष्ट करें, फिर रिपॉजिटरी सदस्यता अलग
से प्रदान करें। प्रतिक्रिया में सुरक्षित उपयोगकर्ता मेटाडेटा शामिल है, पासवर्ड या उसका हैश नहीं। डुप्लिकेट उपयोगकर्ता
नाम या अमान्य अनुरोध को पुनः प्रयास करने से पहले ठीक किया जाना चाहिए। ट्रैक की गई फ़ाइलों, शेल इतिहास, स्क्रीनशॉट या
जारी रिपोर्ट में पासवर्ड या वाहक टोकन संग्रहीत न करें।

<a id="create-and-reset-local-accounts"></a>

## स्थानीय खाते बनाना और रीसेट करना

स्थानीय खाते की पंक्ति में पासवर्ड रीसेट से व्यवस्थापक पुराना पासवर्ड जाने बिना नया सेट करता है। नया पासवर्ड और पुष्टि
दें। पुरानी JWT सत्र अमान्य हो जाते हैं; अपने खाते का रीसेट आपको बाहर करता है। OIDC खाते यह क्रिया नहीं देते। MCP टोकन
निरस्त नहीं होते।

<a id="local-access-groups"></a>

## स्थानीय पहुँच समूह

प्रशासन → उपयोगकर्ता समूह से समूह बनाएँ, नाम बदलें, हटाएँ और सदस्य जोड़ें/हटाएँ। नाम अद्वितीय और गैर-रिक्त हों। चयन में
खोज और पृष्ठ हैं; उपयोगकर्ता कई समूहों में हो सकता है, नेस्टेड समूह नहीं। हटाने पर पुष्टि चाहिए और सदस्यता तथा विरासत
अधिकार हटते हैं, सीधे आवंटन बने रहते हैं।

रिपॉज़िटरी के समूह पहुँच में Viewer या Manager दें, बदलें या हटाएँ। सीधे और विरासत अधिकार जुड़ते हैं; Manager प्राथमिक
है। प्रबंधन के लिए वैश्विक Manager भूमिका भी चाहिए; सिस्टम व्यवस्थापक अप्रतिबंधित हैं। निरसन अगले अनुरोध पर लागू है, जब
तक अन्य अनुदान मौजूद न हो। समूह स्थानीय तथा OIDC खाते लेते हैं, OIDC claims से सिंक नहीं होते।

```text
POST   /api/v1/users                              { username, password, role, firstName?, lastName? }
PUT    /api/v1/users/:id/password                 { newPassword }
GET    /api/v1/user-groups                       ?page=1&perPage=10
POST   /api/v1/user-groups                       { name }
PUT    /api/v1/user-groups/:id                    { name }
DELETE /api/v1/user-groups/:id
GET    /api/v1/user-groups/:id/members            ?page=1&perPage=10
PUT    /api/v1/user-groups/:id/members/:userId
DELETE /api/v1/user-groups/:id/members/:userId
GET    /api/v1/repositories/:id/group-memberships
PUT    /api/v1/repositories/:id/group-memberships/:groupId  { role }
DELETE /api/v1/repositories/:id/group-memberships/:groupId
```
