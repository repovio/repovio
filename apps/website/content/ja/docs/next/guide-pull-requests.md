<a id="browse-and-filter"></a>

## 参照とフィルタリング

**[概要] → [プル リクエスト]**
を開きます。リスト、概要、フィルターの選択、および詳細では、リポジトリのメンバーシップが使用されます。タイトルまたは番号で検索します。プロバイダー、リポジトリ、ライフサイクル、作成者、譲受人、ドラフト状態、ワークフロー ステータス、承認要件、ラベル、更新時間でフィルターします。更新された日付の境界には UTC が含まれます。選択した複数のラベルがすべて一致する必要があります。テーブル コントロールを使用して、並べ替え、表示される列、ページネーションを変更します。サマリー カードは、未解決の変更、下書き、失敗したワークフロー、およびワークフローの承認をカウントします。 GitLab マージリクエストという用語を使用します。詳細には、ソース/ターゲット ブランチ、ドラフト状態、ライフサイクル、および集計ワークフロー ステータスが表示されます。集計では、リンクされた各ワークフローの最新の実行が使用されます。失敗した結果は、実行中、保留中、キャンセル、成功、不明の結果より優先されます。ワークフローの承認要件は、コードレビューの承認、マージの承認、またはマージ競合インジケーターではありません。

<a id="inspect-details"></a>

## 詳細を検査する

行を選択して開きます Repovio 詳細ページ。 ID、リポジトリ、作成者、譲受人、ラベル、マイルストーン、プロバイダーの状態、タイムスタンプ、サニタイズされた Markdown の説明を確認します。リンクされたワークフロー コンテキストが利用可能な場合に表示されます。埋め込み HTML と安全でないマークアップは削除されます。コメント、反応、添付ファイル、コードの差分は同期されません。プロバイダーのリンクを使用して、コメント、割り当て、ラベル付け、閉じる、レビュー、承認、またはマージを行います。 Repovio これらの書き込みはいずれも実行されません。

<a id="synchronization-and-failures"></a>

## 同期と失敗

署名付き Webhook は、15 秒の結合ウィンドウの後にリポジトリ固有の読み取りをキューに入れます。 30 分間の調整で、見逃したイベントがカバーされます。ブラウザを更新すると、保存されたデータが再ロードされます。レコードが存在しない場合は、フィルターをクリアし、リポジトリの有効化とメンバーシップを確認し、検査します。
[同期ジョブ](/docs/next/guide-jobs)。保持により、古いクローズされたレコードが削除される可能性があります。アクセスできない詳細ページは、アクセスが取り消されているか、レコードが削除されていることを示している可能性があります。リストに戻ります。 API 回復後の再試行リクエストの失敗。
