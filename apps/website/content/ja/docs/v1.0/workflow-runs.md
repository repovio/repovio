> アーカイブされたソース スナップショット。製品ラベルはRepovioを使用します。このリリースのタグ付きデプロイメント ファイルの構成識別子とコンテナー参照を変更せずに使用します。

<a id="browse-retained-runs"></a>

## 保持された実行を参照する

**[概要] → [ワークフローの実行] → [すべての実行]**
を開きます。結果の範囲は、アクセス可能なリポジトリと保持された履歴に限定されます。リポジトリ、プロバイダー、ステータス、および期間のフィルターを使用します (期間は秒単位で入力します)。すべての実行にはテキスト検索ボックスがありません。 「要注意」では、検索と詳細な作成/開始列が追加されます。列を並べ替え、表示される列を変更し、結果をページ分割します。期待される実行が見つからない場合はフィルターをクリアします。

行は、ワークフローとリポジトリ、プロバイダー、正規化されたステータス、プロバイダーのタイムスタンプ、および提供された期間を識別します。キューに登録されている実行または未完了の実行では、完了時間や最終期間が不足している可能性があります。正規化された状態は、`queued`、`running`、`success`、`failed`、`cancelled`、`skipped`、および
`unknown` です。不明な状態はプロバイダーで確認する必要があります。

<a id="open-a-run"></a>

## 実行を開く

外部行アクションを使用して、プロバイダーの実行とそのログを開きます。 Repovio は、個別の編集可能な実行画面、プロバイダー アーティファクトのダウンロード、完全なログの同期を提供しません。承認、再実行、キャンセル、またはディスパッチは、プロバイダー アカウントを持つプロバイダーでのみ行ってください。現在の障害の場合は、[注意が必要です](/docs/v1.0/needs-attention)
を使用します。ゲートには [承認待ち](/docs/v1.0/awaiting-approval) を使用します。

<a id="missing-or-stale-history"></a>

## 履歴が見つからないか古い

空のテーブルは、フィルタと権限に一致するレコードが保持されていないことを意味します。保持すると古い実行を削除できます。リポジトリの有効化、メンバーシップ、ワークフローの許可/拒否パターン、および
[同期ジョブ](/docs/v1.0/guide-jobs)
を確認します。ページを更新すると、保存されたデータが再ロードされます。永続的な同期キューはバイパスされません。 API 回復後にロード エラーを再試行します。
