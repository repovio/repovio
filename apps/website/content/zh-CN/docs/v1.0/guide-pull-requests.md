<a id="browse-and-filter"></a>

## 浏览和过滤

打开**概述 → 拉取请求**。列表、摘要、过滤器选项和详细信息使用存储库成员身份。按标题或编号搜索；按提供者、存储库、生命周期、作者、受让人、草稿状态、工作流程状态、批准要求、标签和更新时间进行过滤。更新日期边界包含 UTC。多个选定的标签必须全部匹配。使用表格控件更改排序、可见列和分页。摘要卡对未完成的更改、草稿、失败的工作流程和工作流程审批进行计数。 GitLab 使用术语“合并请求”。详细信息显示源/目标分支、草稿状态、生命周期和聚合工作流状态。聚合使用每个链接的工作流程的最新运行；失败的结果优先于正在运行、待处理、已取消、成功和未知的结果。工作流批准要求不是代码审查批准、合并批准或合并冲突指示器。

<a id="inspect-details"></a>

## 检查详细信息

选择一行以打开其 Repovio 详细信息页面。查看身份、存储库、作者、受让人、标签、里程碑、提供者状态、时间戳和经过净化的 Markdown 描述。链接的工作流程上下文可用时会显示。嵌入的 HTML 和不安全的标记已被删除。评论、反应、附件和代码差异不同步。使用提供者链接来评论、分配、标记、关闭、审查、批准或合并。 Repovio 不执行任何写入操作。

<a id="synchronization-and-failures"></a>

## 同步和失败

签名的 webhook 在 15 秒合并窗口后将特定于存储库的读取排入队列； 30 分钟的核对涵盖了错过的事件。浏览器刷新会重新加载存储的数据。如果记录不存在，请清除过滤器、检查存储库启用和成员身份，并检查
[同步任务](/docs/v1.0/guide-jobs)。保留可以删除旧的关闭记录。无法访问的详细信息页面可能表明访问权限被撤销或记录被删除；返回列表。 API 恢复后重试请求失败。
