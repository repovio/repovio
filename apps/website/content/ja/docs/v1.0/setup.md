---
title: '初回実行時のセットアップ'
description: '最初のローカル管理者を作成し、1 回限りのセットアップを理解します。'
---

> アーカイブされたソース スナップショット。製品ラベルはRepovioを使用します。このリリースのタグ付きデプロイメント ファイルの構成識別子とコンテナー参照を変更せずに使用します。

<a id="before-setup"></a>

## セットアップ前

[導入](/docs/v1.0/deployment)
を使用して、API、Web アプリケーション、および PostgreSQL をデプロイします。インストールURLを開きます。ユーザーが存在しない場合、Repovio はブラウザを
`/auth/setup`
に誘導します。既存のインストールではアカウントが保持され、代わりにサインインが開かれます。セットアップでは、プロバイダー アカウントではなく、ローカル Repovio アカウントが作成されます。

<a id="create-the-administrator"></a>

## 管理者を作成する

オプションの姓名、一意のユーザー名、パスワード、およびパスワードの確認を入力します。パスワードには 12 文字以上が必要です。セットアップ フォームを一度送信し、リクエストを待ちます。セットアップが成功すると、最初のシステム管理者がサインインします。検証エラーがあると、フォームは修正できる状態になります。別のオペレーターが最初にセットアップを完了した場合は、既存のアカウントを使用して
[サインイン](/docs/v1.0/sign-in) に進みます。

<a id="continue-configuration"></a>

## 設定を続行します

[プロバイダーアカウント](/docs/v1.0/provider-accounts) を接続し、[リポジトリ](/docs/v1.0/repositories)
を選択して、[同期ジョブ](/docs/v1.0/guide-jobs)
を検査します。ローカル ユーザーは、保護された API を通じて作成できます。 [ユーザー] ページにはアカウントがリストされ、削除と MCP アクセスが管理されます。あるいは、アイデンティティ プロバイダーが管理するアカウント用に
[OIDC](/docs/v1.0/authentication) を構成します。新しい非管理者には、明示的なリポジトリ メンバーシップが必要です。

セットアップが失敗した場合は、認証情報を公開せずに API/データベースの可用性と展開ログを確認します。セットアップを繰り返すためにデータベースをリセットしないでください。既存のローカル管理者については、[パスワードの回復](/docs/v1.0/authentication#reset-a-forgotten-password)
を参照してください。
