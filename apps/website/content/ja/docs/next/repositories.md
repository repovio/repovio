<a id="browse-and-open-details"></a>

## 詳細を参照して開きます

表からリポジトリを開くと、概要、ワークフロー実行、Issue、Pull Request、セキュリティ警告、設定を切り替えられます。
アクティビティページは対象リポジトリに限定され、フィルター、並べ替え、ページ分割、行からの移動に対応します。
警告には管理権限が必要で、設定はシステム管理者のみ利用できます。プロバイダーリンクは外部リポジトリを開きます。

概要には基本情報、保持期間、最終同期、データの経過時間、間隔、現在のジョブ、最近の活動が表示されます。
待機中・実行中のジョブは進捗を示し、警告やエラーは機密情報を含まない分類で表示されます。

<a id="add-and-maintain-tracking"></a>

## 追跡の追加と維持

リポジトリを追加できるのはシステム管理者のみです。有効なプロバイダー アカウントを選択し、検出を待って、1 つ以上の追跡されていないリポジトリを選択します。すでに追跡されているリポジトリは除外されます。複数追加の一部が失敗した場合、成功した選択は追加されたままとなり、失敗した選択のみが再試行のために残ります。空のプロバイダー リストでは、最初に有効な
[プロバイダーアカウント](/docs/next/provider-accounts) に接続する必要があります。

管理者は、追跡の有効化/無効化、**プロバイダー データの更新**、読み取り専用同期のキューへの登録を行うことができます。リポジトリ ID は、プロバイダ アカウントと安定したプロバイダ リポジトリ ID を使用します。名前変更/転送では、履歴、フィルター、メンバーシップ、およびチャネルが保存されます。メタデータの更新では、古いパスにある別の ID が再割り当てされるのではなく、拒否されます。無効化されたリポジトリは、保存されたデータを保持しますが、同期への参加を停止します。

<a id="repository-settings-sections"></a>

## リポジトリ設定のセクション

リポジトリ設定には五つの補助タブがあります。各セクションは利用可能な幅を使い、狭い画面では入力欄を縦に並べます。タブのリンクは共有でき、再読み込みや戻る・進むでも選択が復元されます。既定は「一般」です。

| セクション             | 目的                             | アドレス                     |
| ---------------------- | -------------------------------- | ---------------------------- |
| 一般                   | 保持期間の上書き                 | `/repositories/:id/settings` |
| Webhook                | リポジトリ Webhook の設定        | `?tab=webhook`               |
| ワークフローフィルター | 許可・拒否のワークフローパターン | `?tab=workflow-filters`      |
| メンバー               | ユーザーの直接アクセスとロール   | `?tab=members`               |
| グループのアクセス権   | ローカルグループの追加アクセス   | `?tab=groups`                |

同じ設定画面内でタブを切り替えても、未保存の入力と処理中のリクエストは保持されます。設定を離れるか別のリポジトリを開くと、生成した Webhook シークレットを含む下書きは破棄されます。変更を保存するには各セクションの保存または割り当て操作を使ってください。

簡易詳細ダイアログは削除されました。旧形式の `?repository=` リンクは概要を開きます。詳細ページには更新、同期、プロバイダーへのリンク、ローカル削除が引き続き用意されています。URL を変更しても閲覧者や管理者の設定アクセス権は増えません。

<a id="retention-filters-and-memberships"></a>

## 保持、フィルター、およびメンバーシップ

管理者は、ワークフローの実行、発行、プルリクエストの保持オーバーライドをそれぞれ 1 ～ 3650 日で個別に設定します。空の値は、対応する
[システムのデフォルト](/docs/next/settings-system) を復元します。ワークフロー フィルターは **ALLOW** および**DENY**
グロブ パターンを受け入れます。拒否が優先されます。空ではないパターンを追加するか、既存のパターンを削除します。制限的なフィルターは実行の不在を説明する可能性があります。

メンバーシップで、管理者以外のユーザーを閲覧者またはマネージャーとして追加したり、リポジトリの役割を変更したり、アクセス権を削除したりできます。管理者はすでに無制限のアクセス権を持っているため、メンバーの選択から除外されます。グローバル マネージャーは、セキュリティ アラートなどのリポジトリ管理機能を利用するためにマネージャー メンバーシップを必要とします。

<a id="webhooks-and-failures"></a>

## Webhook と障害

リポジトリ Webhook カードには、コールバック URL、構成された状態、プロバイダーの指示、および最後の配信が表示されます。シークレットの生成/コピー、設定の保存、明示的な確認付きのローテーション、または設定の削除が可能です。欠落しているパブリック URL は、プロバイダーを登録する前に修正する必要があります。シークレットは構成中にのみ表示されます。秘密のマネージャーに保管してください。セットアップと検証については、[リポジトリ Webhook](/docs/next/provider-webhooks)
に従ってください。

閲覧者と管理担当者は概要で読み取り専用のリポジトリ情報を確認します。設定はシステム管理者専用です。原因を解消してから再試行し、同期エラーは[ジョブ](/docs/next/guide-jobs)で確認してください。

<a id="local-user-and-group-management"></a>

## ローカルアクセスグループ

リポジトリのグループアクセスで Viewer または Manager を付与し、変更や削除ができます。直接権限と継承権限を合算し、Manager が優先します。管理には全体の Manager 役割も必要で、システム管理者は制限されません。取り消しは次の要求で有効ですが、別の権限があればアクセスは残ります。ローカルと OIDC アカウントを扱い、OIDC クレームからの同期は行いません。

[ローカルアクセスグループ](/docs/next/users#local-access-groups)

<a id="delete-local-tracking"></a>

## ローカル追跡の削除

システム管理者は詳細ページで **リポジトリを削除** を選択できます。確認にはリポジトリ名が表示され、ローカルのワークフロー、実行、Issue、Pull Request、セキュリティ警告、設定、アクセス権の割り当て、Webhook 履歴、同期状態、関連する通知履歴が完全に削除されることが説明されます。プロバイダーアカウントとプロバイダー側のリポジトリデータは変更されません。

同期中は削除できません。完了後に再試行してください。保留中の同期要求もリポジトリとともに削除されます。通知の購読からこのリポジトリのフィルターが削除されます。このリポジトリだけを対象とする購読は、全体への購読になるのではなく削除されます。共有チャンネルは維持されます。

既存のプロバイダー選択からリポジトリを再度追加できます。以前のローカル履歴や設定を復元せず、新しい追跡が開始されます。
