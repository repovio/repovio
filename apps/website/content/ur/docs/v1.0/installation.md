> محفوظ شدہ ماخذ سنیپ شاٹ۔ پروڈکٹ لیبلز Repovio استعمال کرتے ہیں۔ اس ریلیز کی ٹیگ شدہ تعیناتی فائلوں سے کنفیگریشن شناخت
> کنندگان اور کنٹینر حوالہ جات کو بغیر تبدیلی کے استعمال کریں۔

Repovio صرف پڑھنے کے لیے ورک فلو اسٹیٹس ڈیش بورڈ ہے۔ یہ مجاز صارفین کو GitHub، GitLab، Forgejo، یا Gitea پر کسی بھی چیز
کو تخلیق، دوبارہ چلانے، منظوری یا حذف کیے بغیر ریپوزٹری سرگرمی کا معائنہ کرنے دیتا ہے۔

<a id="before-you-begin"></a>

## شروع کرنے سے پہلے

آپ کو Repovio انسٹالیشن کے URL اور مقامی یا کنفیگر شدہ OIDC اکاؤنٹ کی ضرورت ہے۔ پہلا منتظم ایک وقتی سیٹ اپ مکمل کرتا ہے۔
اضافی مقامی صارفین کو محفوظ API کے ذریعے فراہم کیا جاتا ہے، یا صارف کنفیگرڈ OIDC کے ذریعے سائن ان کرتے ہیں۔ فراہم کنندہ
کے ڈیٹا تک رسائی آپ کے کردار اور ذخیرہ کی رکنیت پر منحصر ہے۔ سائن ان کرنے سے ہر ترتیب شدہ ذخیرہ خود بخود ظاہر نہیں ہوتا
ہے۔

Repovio ایپلیکیشن کے تین کردار استعمال کرتا ہے:

- **ناظر** واضح طور پر تفویض کردہ ریپوزٹریز، ورک فلو، مسائل، اور پل کی درخواستوں کا معائنہ کر سکتا ہے۔
- **مینیجر** کے پاس پڑھنے کی رسائی ہے اور وہ ان ریپوزٹریوں کے لیے حفاظتی انتباہات کا معائنہ کر سکتا ہے جہاں رکنیت
  بھی**مینیجر** ہے۔ نوٹیفکیشن چینلز، سبسکرپشنز، ٹیسٹس اور ہسٹری کا انتظام عالمی سطح پر سسٹم ایڈمنسٹریٹرز کے ذریعے کیا
  جاتا ہے۔
- **سسٹم ایڈمنسٹریٹر** ہر ریپوزٹری تک رسائی حاصل کرسکتا ہے اور فراہم کنندہ کے اکاؤنٹس، ریپوزٹریز، ممبرشپ، صارفین، MCP
  ٹوکنز، اور ایپلیکیشن ڈیفالٹس کا انتظام کرسکتا ہے۔

درخواست کے کردار کبھی بھی GitHub، GitLab، Forgejo، یا Gitea پر تحریری رسائی نہیں دیتے ہیں۔ اگر کوئی عمل فراہم کنندہ کی
حالت کو تبدیل کرتا ہے، Repovio کارروائی کرنے کے بجائے فراہم کنندہ کے انٹرفیس کو کھولتا ہے۔

<a id="recommended-first-session"></a>

## تجویز کردہ پہلا سیشن

1. [سائن ان کریں۔](/docs/v1.0/sign-in)، [نیویگیشن](/docs/v1.0/navigation) سیکھیں، اور [تلاش کریں](/docs/v1.0/search) کو
   آزمائیں۔
2. [ڈیش بورڈ](/docs/v1.0/guide-dashboard)، [تمام رنز](/docs/v1.0/workflow-runs)،
   [توجہ کی ضرورت ہے۔](/docs/v1.0/needs-attention)، اور [منظوری کا انتظار ہے۔](/docs/v1.0/awaiting-approval) کا جائزہ
   لیں۔
3. [مسائل](/docs/v1.0/guide-issues) اور [پل ریکویسٹس](/docs/v1.0/guide-pull-requests) کا معائنہ کریں۔
4. جو ڈیٹا آپ دیکھ سکتے ہیں اسے سمجھنے کے لیے [مخزن](/docs/v1.0/repositories) کھولیں۔
5. منتظمین [نوٹیفکیشن چینلز](/docs/v1.0/notifications) اور [ایونٹ سبسکرپشنز](/docs/v1.0/notification-rules) کو ترتیب
   دیتے ہیں۔

سسٹم کے منتظمین کو پھر [انتظامیہ اور ترتیبات](/docs/v1.0/provider-accounts) کے ساتھ جاری رکھنا چاہیے۔ تعیناتی، فراہم
کنندہ کی رجسٹریشن، ویب ہک سیٹ اپ، بیک اپ، اور ریکوری متعلقہ ہینڈ بک کے صفحات سے منسلک ہیں۔

<a id="when-a-page-is-empty-or-unavailable"></a>

## جب کوئی صفحہ خالی ہو یا دستیاب نہ ہو۔

ایک خالی صفحہ کا مطلب یہ ہو سکتا ہے کہ کوئی مماثل فراہم کنندہ کا ڈیٹا ہم آہنگ نہیں کیا گیا ہے، یہ کہ فلٹرز تمام نتائج کو
خارج کر دیتے ہیں، یا یہ کہ آپ کے اکاؤنٹ میں مخزن کے لیے کوئی رکنیت نہیں ہے۔ فعال فلٹرز کو صاف کریں اور پہلے ریپوزٹری
سلیکشن کو چیک کریں۔ لوڈ ایرر میسج کا مطلب ہے کہ درخواست کردہ ڈیٹا کو بازیافت نہیں کیا جا سکا۔ صفحہ کی کارروائی کی دوبارہ
کوشش کریں اور اگر خرابی برقرار رہتی ہے تو انسٹالیشن ایڈمنسٹریٹر سے API اور سنکرونائزیشن جابز کا معائنہ کرنے کو کہیں۔
