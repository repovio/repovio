## Установленная документация по API

Каждый сервер API Repovio предоставляет интерактивную документацию по API по адресу `/docs`. В локальной разработке
откройте `http://localhost:3001/docs`. Конечные точки REST используют базовый путь `/api/v1`.

Для развертывания используйте доступный извне источник API и путь, настроенный вашим обратным прокси-сервером. Например,
если сервер API доступен по адресу `https://repovio.example.com`, его документация может быть доступна по адресу
`https://repovio.example.com/docs`. Веб-приложение не проксирует этот маршрут автоматически; явно настройте свой прокси,
если вы хотите его открыть. `/api/v1/docs` не является маршрутом документации.

Установленная ссылка описывает работающее приложение. Запросы, сделанные из этой интерактивной ссылки, используют ваш
экземпляр и требуют аутентификации и разрешений, документированных для каждой операции. См.
[Аутентификация](/docs/v2.0/authentication) для входа в систему и настройки учетной записи. Маркеры доступа MCP
предназначены для [Клиенты MCP](/docs/v2.0/mcp), а не как обычные токены носителя REST.

<a id="static-release-reference"></a>

## Ссылка на статическую версию

[Справочник по API](/docs/v2.0/api-reference) на этом веб-сайте представляет собой снимок, доступный только для чтения,
созданный на основе точной версии приложения выбранного выпуска. Ему не требуется работающий экземпляр Repovio, и он не
отправляет запросы API. Выберите версию, соответствующую вашей установке; установленная страница `/docs` остается
авторитетной для вашей работающей сборки.

Выполняйте поиск по методу, пути или описанию, проверяйте параметры и схемы ответов или загрузите полную версию OpenAPI
JSON со справочной страницы. Идентификаторы схемы и описания API сохраняют язык созданного контракта.
