<a id="before-setup"></a>

## Перед установкой

Разверните API, веб-приложение и PostgreSQL с помощью [Развертывание](/docs/v2.0/deployment). Откройте URL-адрес
установки. Когда пользователь не существует, Repovio направляет браузер на `/auth/setup`. Существующие установки
сохраняют свои учетные записи и вместо этого открывают вход в систему. Программа установки создает локальную учетную
запись Repovio, а не учетную запись поставщика.

<a id="create-the-administrator"></a>

## Создаем администратора

Введите необязательное имя и фамилию, уникальное имя пользователя, пароль и подтверждение пароля. Пароли требуют не
менее 12 символов. Отправьте форму настройки один раз и дождитесь запроса; успешная настройка приписывается первому
системному администратору. Ошибки проверки оставляют форму доступной для исправления. Если другой оператор первым
выполнил настройку, перейдите к [Войти](/docs/v2.0/sign-in) с существующей учетной записью.

<a id="continue-configuration"></a>

## Продолжить настройку

Подключите [учетная запись провайдера](/docs/v2.0/provider-accounts), выберите [репозитории](/docs/v2.0/repositories) и
проверьте [задания синхронизации](/docs/v2.0/guide-jobs). Локальных пользователей можно создавать через защищенный API;
на странице «Пользователи» перечислены учетные записи и можно управлять удалением и доступом к MCP. Альтернативно
настройте [OIDC](/docs/v2.0/authentication) для учетных записей, управляемых поставщиком удостоверений. Новым
пользователям, не являющимся администраторами, необходимо явное членство в репозитории.

Если установка не удалась, проверьте доступность API/базы данных и журналы развертывания, не публикуя учетные данные. Не
сбрасывайте базу данных, чтобы повторить настройку. См.
[Восстановление пароля](/docs/v2.0/authentication#reset-a-forgotten-password) для существующего локального
администратора.

<a id="local-user-and-group-management"></a>

## Создание и сброс локальных учетных записей

В Администрирование → Пользователи выберите создание пользователя. Укажите уникальное имя, необязательные имя и фамилию,
пароль 12–256 символов с подтверждением и роль; по умолчанию Viewer. Создание доступно и с OIDC. OIDC-записи создаются
провайдером и не связываются по совпадению локального имени.

[Локальные группы доступа](/docs/v2.0/users#local-access-groups)
