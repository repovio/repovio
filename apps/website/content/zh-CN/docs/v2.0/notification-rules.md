## 配置订阅

系统管理员打开 [渠道](/docs/v2.0/notifications) 并在其创建/编辑对话框中配置事件订阅。旧版 `/notifications/rules`
路由重定向至 Channels；没有单独的规则管理屏幕。本页记录了通道对话工作流程。

选择工作流程成功、失败或恢复；拉取请求打开、关闭、重新打开或合并；问题已打开、关闭或重新打开；以及支持的依赖项、代码或秘密警报打开/解决的事件。为每个事件选择存储库限制。空的存储库选择意味着所有适用的存储库，而不是没有。工作流名称模式仅适用于工作流事件。保存频道以保留其订阅。

<a id="preview-matches"></a>

## 预览比赛

仅当至少选择一个工作流事件时预览才可用；仅非工作流订阅会禁用它。保存前使用预览检查最多 20 个最近匹配的工作流程记录。匹配确认当前过滤条件与保留数据的关系；它不会将交付排队。区分不匹配与从未同步、同步失败或部分数据通知。当源数据不可用时，扩大存储库/模式选择或检查
[同步任务](/docs/v2.0/guide-jobs)。

初始同步为生命周期事件建立静默基线，并且不会用旧的打开/关闭转换淹没通道。稍后观察到的转变可以产生交付。提供程序的可用性和读取权限限制了可以观察到的安全事件。 Repovio 从不更改提供者资源来进行规则匹配。

如果预览或保存失败，请保留表单值，检查 API 状态，然后重试。仅空预览并不能证明未来事件不会匹配或每个选定的存储库已成功同步。
