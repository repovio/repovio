> আর্কাইভ সোর্স স্ন্যাপশট। পণ্য লেবেল Repovio ব্যবহার করে। অপরিবর্তিত এই রিলিজের ট্যাগ করা ডিপ্লয়মেন্ট ফাইল থেকে
> কনফিগারেশন শনাক্তকারী এবং কন্টেইনার রেফারেন্স ব্যবহার করুন।

<a id="before-setup"></a>

## সেটআপ করার আগে

[স্থাপনা](/docs/v1.0/deployment) ব্যবহার করে API, ওয়েব অ্যাপ্লিকেশন এবং PostgreSQL স্থাপন করুন। ইনস্টলেশন URL খুলুন.
যখন কোনো ব্যবহারকারী উপস্থিত না থাকে, Repovio ব্রাউজারটিকে `/auth/setup`-এ নির্দেশ করে। বিদ্যমান ইনস্টলেশনগুলি তাদের
অ্যাকাউন্টগুলি ধরে রাখে এবং পরিবর্তে সাইন-ইন ওপেন করে৷ সেটআপ একটি স্থানীয় Repovio অ্যাকাউন্ট তৈরি করে, একটি প্রদানকারী
অ্যাকাউন্ট নয়।

<a id="create-the-administrator"></a>

## প্রশাসক তৈরি করুন

একটি ঐচ্ছিক প্রথম এবং শেষ নাম, একটি অনন্য ব্যবহারকারীর নাম, একটি পাসওয়ার্ড এবং পাসওয়ার্ড নিশ্চিতকরণ লিখুন৷
পাসওয়ার্ডের জন্য কমপক্ষে 12টি অক্ষরের প্রয়োজন। একবার সেটআপ ফর্ম জমা দিন এবং অনুরোধের জন্য অপেক্ষা করুন; প্রথম সিস্টেম
অ্যাডমিনিস্ট্রেটরে সফল সেটআপ লক্ষণ। বৈধতা ত্রুটি সংশোধনের জন্য উপলব্ধ ফর্ম ছেড়ে. যদি অন্য অপারেটর প্রথমে সেটআপ সম্পন্ন
করে, তাহলে বিদ্যমান অ্যাকাউন্টের সাথে [সাইন ইন করুন](/docs/v1.0/sign-in)-এ চালিয়ে যান।

<a id="continue-configuration"></a>

## কনফিগারেশন চালিয়ে যান

একটি [প্রদানকারী অ্যাকাউন্ট](/docs/v1.0/provider-accounts) সংযোগ করুন, [সংগ্রহস্থল](/docs/v1.0/repositories) নির্বাচন
করুন এবং [সিঙ্ক্রোনাইজেশন কাজ](/docs/v1.0/guide-jobs) পরিদর্শন করুন৷ স্থানীয় ব্যবহারকারীদের সুরক্ষিত API এর মাধ্যমে
তৈরি করা যেতে পারে; ব্যবহারকারীদের পৃষ্ঠা অ্যাকাউন্ট তালিকাভুক্ত করে এবং মুছে ফেলা এবং MCP অ্যাক্সেস পরিচালনা করে।
বিকল্পভাবে পরিচয়-প্রদানকারী-পরিচালিত অ্যাকাউন্টগুলির জন্য [OIDC](/docs/v1.0/authentication) কনফিগার করুন। নতুন
অ-প্রশাসকদের সুস্পষ্ট সংগ্রহস্থল সদস্যতা প্রয়োজন।

সেটআপ ব্যর্থ হলে, শংসাপত্র প্রকাশ না করে API/ডাটাবেস উপলব্ধতা এবং স্থাপনার লগগুলি পরীক্ষা করুন। সেটআপের পুনরাবৃত্তি করতে
ডাটাবেস রিসেট করবেন না। একটি বিদ্যমান স্থানীয় প্রশাসকের জন্য
[পাসওয়ার্ড পুনরুদ্ধার](/docs/v1.0/authentication#reset-a-forgotten-password) দেখুন।
