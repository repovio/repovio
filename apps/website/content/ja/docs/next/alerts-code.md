<a id="access-and-provider-support"></a>

## アクセスとプロバイダーのサポート

**[概要] → [セキュリティ アラート] → [コード スキャン アラート]**
を開きます。マネージャーにはリポジトリへの管理アクセスが必要です。システム管理者はすべてのリポジトリを検査できます。閲覧者はアラート データにアクセスできません。リスト、フィルター オプション、カウンター、詳細、リポジトリ アクティビティ、およびダッシュボード メトリックには、同じアクセス制限が適用されます。

GitHub は、セキュリティ API を通じてこのアラート タイプをサポートしています。 GitLab インスタンス/ライセンスおよびトークンの権限に応じて、依存関係スキャン、SAST、および秘密検出の脆弱性を対応するアラート ビューにマップします。 Forgejo そして Gitea 現在、これらのタイプはサポートされていないと報告されています。使用できないタイプに関する警告は、他の同期スコープに失敗しません。

<a id="review-findings"></a>

## 調査結果を確認する

検索と使用可能なリポジトリ、プロバイダー、重大度、および状態のフィルター、並べ替え、表示される列、およびページネーションを使用します。州には以下が含まれます
`OPEN`、 `RESOLVED`、 そして
`DISMISSED`;重大度には、重大、高、中、低、情報、不明が含まれます。コード フィルターにはさらに、スキャナー、ルール、専用のファイル パス セレクターが含まれています。更新日の境界と種類固有のテキスト検索は、大きなリストを絞り込むのに役立ちます。スキャナー、ルール、重大度、ファイルの安全な場所、および検出結果の状態を検査する検出結果を選択します。 Repovio ホワイトリストに登録されたメタデータのみを保存します。生のプロバイダーのペイロード、資格情報、トークンのフラグメント、およびシークレットの値は決して保持されません。欠落しているフィールドは、処理エラーではなくプロバイダーの機能を反映している可能性があります。

**プロバイダーで開く**を使用して調査し、修復します。 Repovio アラートの却下、解決、再オープン、編集は行われません。リポジトリおよびアラートの種類ごとに最初に成功した読み取りによって、サイレント ベースラインが確立されます。後で開かれた、解決された、却下された、または再度開かれたトランジションにより、サブスクライブがトリガーされる可能性があります
[通知チャネル](/docs/next/notifications)。

<a id="empty-unavailable-and-stale-data"></a>

## 空の、使用できない、古いデータ

検出結果が表示されない場合は、フィルターをクリアし、管理メンバーシップを確認します。 [同期ジョブ](/docs/next/guide-jobs)
でサポートされていない種類や権限の警告がないか調べてください。既存の GitHub OAuth アカウントは、`security_events`
による再認証が必要な場合があります。
[プロバイダー OAuth](/docs/next/provider-oauth)を参照してください。回復後に失敗したロードを再試行します。目に見える検出結果がないことは、プロバイダーがリポジトリをスキャンしたこと、またはすべてのアラート タイプがサポートされていることを証明するものではありません。
