## رسائی اور فراہم کنندہ کی مدد

کھولیں **مجموعی جائزہ → سیکیورٹی الرٹس → کوڈ اسکیننگ الرٹس**۔ مینیجرز کو ریپوزٹری تک انتظامی رسائی کی ضرورت ہے۔ سسٹم
ایڈمنسٹریٹر تمام ذخیروں کا معائنہ کر سکتے ہیں۔ ناظرین الرٹ ڈیٹا تک رسائی حاصل نہیں کر سکتے۔ فہرستیں، فلٹر کے اختیارات،
کاؤنٹرز، تفصیلات، ذخیرہ کی سرگرمی، اور ڈیش بورڈ میٹرکس ایک ہی رسائی کی پابندیوں کا اطلاق کرتے ہیں۔

GitHub اس الرٹ قسم کو اپنے سیکیورٹی APIs کے ذریعے سپورٹ کرتا ہے۔ GitLab انحصار سکیننگ، SAST، اور خفیہ کھوج کے خطرات کو
متعلقہ الرٹ ویوز کے لیے نقشہ بناتا ہے، جو مثال/لائسنس اور ٹوکن اجازتوں سے مشروط ہے۔ Forgejo اور Gitea فی الحال ان اقسام
کو غیر تعاون یافتہ کے طور پر رپورٹ کرتے ہیں۔ غیر دستیاب قسم کے لیے ایک انتباہ دیگر مطابقت پذیری کے دائرہ کار کو ناکام
نہیں کرتا ہے۔

<a id="review-findings"></a>

## نتائج کا جائزہ لیں۔

تلاش اور دستیاب ذخیرہ، فراہم کنندہ، شدت، اور ریاستی فلٹرز، چھانٹی، مرئی کالم، اور صفحہ بندی کا استعمال کریں۔ ریاستوں میں
`OPEN`، `RESOLVED`، اور `DISMISSED` شامل ہیں؛ شدت میں اہم، اعلی، درمیانی، کم، معلوماتی، اور نامعلوم شامل ہیں۔ کوڈ فلٹرز
میں اسکینر، قاعدہ، اور ایک سرشار فائل پاتھ سلیکٹر بھی شامل ہے۔ اپ ڈیٹ شدہ تاریخ کی حدیں اور قسم کے مخصوص متن کی تلاش بڑی
فہرستوں کو تنگ کرنے میں مدد کرتی ہے۔ سکینر، قاعدہ، شدت، محفوظ فائل لوکیشن، اور تلاش کرنے کی حالت کا معائنہ کرنے کے لیے
تلاش کا انتخاب کریں۔ Repovio صرف اجازت یافتہ میٹا ڈیٹا اسٹور کرتا ہے۔ خام فراہم کنندہ کے پے لوڈز، اسناد، ٹوکن کے ٹکڑے،
اور خفیہ اقدار کو کبھی بھی برقرار نہیں رکھا جاتا ہے۔ غائب فیلڈز پروسیسنگ کی خرابی کے بجائے فراہم کنندہ کی صلاحیتوں کی
عکاسی کر سکتے ہیں۔

تحقیقات اور تدارک کے لیے **فراہم کنندہ میں کھولیں** کا استعمال کریں۔ Repovio انتباہات کو مسترد، حل، دوبارہ کھولنے، یا
ترمیم نہیں کرتا ہے۔ پہلی کامیاب ریڈی فی ریپوزٹری اور الرٹ قسم ایک خاموش بیس لائن قائم کرتی ہے۔ بعد میں کھولے گئے، حل کیے
گئے، برخاست کیے گئے، یا دوبارہ کھولے گئے ٹرانزیشنز سبسکرائب شدہ [نوٹیفکیشن چینلز](/docs/next/notifications) کو متحرک کر
سکتے ہیں۔

<a id="empty-unavailable-and-stale-data"></a>

## خالی، غیر دستیاب، اور باسی ڈیٹا

فلٹرز صاف کریں اور انتظامیہ کی رکنیت کی تصدیق کریں اگر کوئی نتائج ظاہر نہ ہوں۔ غیر تعاون یافتہ قسموں یا اجازت کے
انتباہات کے لیے [ہم وقت سازی کے کام](/docs/next/guide-jobs) کا معائنہ کریں۔ موجودہ GitHub OAuth اکاؤنٹس کو
`security_events` کے ساتھ دوبارہ اجازت کی ضرورت ہو سکتی ہے۔ [فراہم کنندہ OAuth](/docs/next/provider-oauth) دیکھیں۔ بحالی
کے بعد ناکام بوجھ کی دوبارہ کوشش کریں؛ مرئی نتائج کی عدم موجودگی اس بات کا ثبوت نہیں ہے کہ فراہم کنندہ نے ذخیرہ کو اسکین
کیا ہے یا یہ کہ ہر قسم کی الرٹ معاون ہے۔
