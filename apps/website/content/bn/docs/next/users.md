## অ্যাকাউন্ট পর্যালোচনা করুন

সিস্টেম অ্যাডমিনিস্ট্রেটররা **প্রশাসন → ব্যবহারকারী** খুলছেন। সারণী ব্যবহারকারীর নাম, অবতার/প্রদর্শনের নাম, ভূমিকা,
স্থানীয়/OIDC মূল এবং তৈরি/আপডেট করা টাইমস্ট্যাম্প দেখায়। ভূমিকা দ্বারা ফিল্টার করুন, বাছাই করুন, কলাম পরিবর্তন করুন,
বা পৃষ্ঠা সংখ্যা করুন। ভিউয়ার বা ম্যানেজারের জন্য সংগ্রহস্থল অ্যাক্সেসের জন্য একটি পৃথক
[সংগ্রহস্থল সদস্যপদ](/docs/next/repositories) প্রয়োজন; পরিচয়-প্রদানকারী গোষ্ঠী সেই সদস্যপদ তৈরি করে না।

<a id="provisioning-and-deletion"></a>

## বিধান এবং মুছে ফেলা

প্রশাসন → ব্যবহারকারীর টুলবারে নতুন ব্যবহারকারী বাছুন। অনন্য নাম, ঐচ্ছিক প্রথম/শেষ নাম, 12–256 অক্ষরের পাসওয়ার্ড ও
নিশ্চিতকরণ এবং ভূমিকা দিন; প্রাথমিক Viewer। OIDC চালু থাকলেও তৈরি করা যায়। OIDC পরিচয় প্রদানকারীর মাধ্যমে তৈরি হয়,
মিলে যাওয়া স্থানীয় নাম দিয়ে যুক্ত হয় না।

মুছে ফেলার ক্রিয়া অন্যান্য ব্যবহারকারীদের জন্য উপলব্ধ এবং অবিলম্বে কার্যকর করা হয়; অ্যাকাউন্ট নির্বাচন করার আগে
পর্যালোচনা করুন। আপনি এই API বা স্ক্রিনের মাধ্যমে আপনার নিজের অ্যাকাউন্ট মুছতে পারবেন না। একটি Repovio ব্যবহারকারী মুছে
ফেলা স্থানীয় অ্যাক্সেস সরিয়ে দেয়; এটি GitHub, GitLab, Forgejo, বা Gitea এ কোনো প্রদানকারী অ্যাকাউন্ট মুছে দেয় না।
মুছে ফেলার আগে প্রভাবিত ব্যবহারকারীর অ্যাক্সেস পর্যালোচনা করুন।

<a id="user-mcp-tokens"></a>

## ব্যবহারকারী MCP টোকেন

টোকেন মেটাডেটা তালিকাভুক্ত করতে ব্যবহারকারীর MCP-টোকেন ডায়ালগ খুলুন বা নিশ্চিতকরণ সহ একটি টোকেন প্রত্যাহার করুন৷
অ্যাডমিনিস্ট্রেটররা প্লেইনটেক্সট টোকেন মান পুনরুদ্ধার করতে পারে না বা এই ডায়ালগের মাধ্যমে অন্য ব্যবহারকারীর টোকেন তৈরি
করতে পারে না। ব্যবহারকারীরা [MCP সেটিংস](/docs/next/mcp)-এ তাদের নিজস্ব টোকেন তৈরি করে। খালি তালিকা এবং লোড ত্রুটি
স্বতন্ত্র; API পুনরুদ্ধারের পরে পুনরায় চেষ্টা করুন। সমর্থন প্রতিবেদন বা স্ক্রিনশটগুলিতে টোকেন মানগুলি কখনই অনুলিপি
করবেন না।

<a id="local-user-api"></a>

## API এর মাধ্যমে স্থানীয় ব্যবহারকারীর ব্যবস্থা করুন

অ্যাডমিনিস্ট্রেটর বাহক প্রমাণীকরণ এবং `Content-Type: application/json` সহ `POST /api/v1/users` পাঠাতে HTTPS-এ একটি API
ক্লায়েন্ট ব্যবহার করুন। ক্লায়েন্টের সুরক্ষিত ইনপুটগুলিতে স্থানধারক প্রতিস্থাপন করে এই অনুরোধের মূল অংশটি সরবরাহ করুন:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

বৈধ ভূমিকা হল `VIEWER`, `MANAGER`, এবং `SYSTEM_ADMIN`৷ শুধুমাত্র প্রয়োজনীয় ভূমিকা বরাদ্দ করুন, তারপর আলাদাভাবে
সংগ্রহস্থল সদস্যপদ প্রদান করুন। প্রতিক্রিয়াটিতে নিরাপদ ব্যবহারকারী মেটাডেটা রয়েছে, পাসওয়ার্ড বা এর হ্যাশ নয়। একটি
ডুপ্লিকেট ব্যবহারকারীর নাম বা অবৈধ অনুরোধ পুনরায় চেষ্টা করার আগে সংশোধন করা আবশ্যক. ট্র্যাক করা ফাইল, শেল ইতিহাস,
স্ক্রিনশট বা ইস্যু রিপোর্টে পাসওয়ার্ড বা বাহক টোকেন সংরক্ষণ করবেন না।

<a id="create-and-reset-local-accounts"></a>

## স্থানীয় অ্যাকাউন্ট তৈরি ও রিসেট

স্থানীয় অ্যাকাউন্টের সারিতে পাসওয়ার্ড রিসেট দিয়ে প্রশাসক পুরোনোটি ছাড়াই নতুন পাসওয়ার্ড দেন। নতুন পাসওয়ার্ড ও
নিশ্চিতকরণ লিখুন। আগের JWT সেশন অকার্যকর হয়; নিজের রিসেটে লগআউট হয়। OIDC অ্যাকাউন্টে এই কাজ নেই। MCP টোকেন বাতিল হয়
না।

<a id="local-access-groups"></a>

## স্থানীয় প্রবেশাধিকার দল

প্রশাসন → ব্যবহারকারী দল থেকে তৈরি, নাম বদল, মুছে ফেলা ও সদস্য যোগ/সরান। নাম অনন্য ও খালি নয়। নির্বাচন অনুসন্ধান ও
পৃষ্ঠা সমর্থন করে; ব্যবহারকারী একাধিক দলে থাকতে পারে, নেস্টেড দল নয়। মুছতে নিশ্চিতকরণ লাগে এবং সদস্যতা ও উত্তরাধিকার
অধিকার মুছে যায়, সরাসরি বরাদ্দ থাকে।

রিপোজিটরির দলীয় প্রবেশে Viewer বা Manager দিন, বদলান বা সরান। সরাসরি ও উত্তরাধিকার অধিকার মেলে; Manager অগ্রাধিকার
পায়। ব্যবস্থাপনায় বৈশ্বিক Manager ভূমিকাও লাগে; সিস্টেম প্রশাসক সীমাহীন। অন্য অনুমতি না থাকলে পরের অনুরোধে বাতিল
কার্যকর হয়। দল স্থানীয় ও OIDC অ্যাকাউন্ট নেয়, OIDC claims থেকে সমন্বয় হয় না।

```text
POST   /api/v1/users                              { username, password, role, firstName?, lastName? }
PUT    /api/v1/users/:id/password                 { newPassword }
GET    /api/v1/user-groups                       ?page=1&perPage=10
POST   /api/v1/user-groups                       { name }
PUT    /api/v1/user-groups/:id                    { name }
DELETE /api/v1/user-groups/:id
GET    /api/v1/user-groups/:id/members            ?page=1&perPage=10
PUT    /api/v1/user-groups/:id/members/:userId
DELETE /api/v1/user-groups/:id/members/:userId
GET    /api/v1/repositories/:id/group-memberships
PUT    /api/v1/repositories/:id/group-memberships/:groupId  { role }
DELETE /api/v1/repositories/:id/group-memberships/:groupId
```
