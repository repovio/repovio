<a id="current-failures"></a>

## 現在の障害

**ワークフローが実行中 → 注意が必要**を開きます。過去の失敗した実行とは異なり、このキューには、最新の完了した実行が失敗したアクション可能なワークフロー コンテキストが保持されます。新しい正常な実行、クローズされた関連変更、またはマージされた変更は、同期後にコンテキストを削除します。古いブランチ スコープの実行は、開始時にアクティブだったプル/マージ リクエストに関連付けることができます。サイドバー バッジは、同じ権限スコープのキューを使用します。

利用可能なテーブル コントロールを検索して使用し、ワークフロー/リポジトリ コンテキストを絞り込みます。ログと修復のために外部実行リンクを開きます。関連する変更が存在する場合はそれを開きます。 Repovio ワークフローを再実行、キャンセル、編集、またはディスパッチすることはありません。

<a id="diagnose-missing-or-stale-entries"></a>

## 欠落しているエントリまたは古いエントリを診断します

置換の実行が成功した後は、空の結果が正しい場合があります。古い障害の場合は次を使用します
[すべての実行](/docs/v2.0/workflow-runs)。欠落したコンテキストを欠落データとして扱う前に、フィルターをクリアし、リポジトリのメンバーシップを確認してください。プロバイダーのアクションは非同期的に観察されます。検査する
[同期ジョブ](/docs/v2.0/guide-jobs)
状態が古いままの場合。ロードエラーとリクエストエラーは空のキューとは別のものです。 API リカバリ後に再試行してください。
