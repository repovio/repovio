<a id="review-accounts"></a>

## Проверить аккаунты

Системные администраторы открывают **Администрирование → Пользователи**. В таблице показаны имя пользователя,
аватар/отображаемое имя, роль, локальное/OIDC происхождение, а также временные метки создания/обновления. Фильтруйте по
роли, сортируйте, меняйте столбцы или разбивайте на страницы. Для доступа к репозиторию для средства просмотра или
менеджера требуется отдельный [членство в репозитории](/docs/v1.0/repositories); группы поставщиков удостоверений не
создают такое членство.

<a id="provisioning-and-deletion"></a>

## Предоставление и удаление

На странице «Пользователи» нет формы создания пользователя или редактирования пользователя. Дополнительные локальные
пользователи создаются с помощью защищенного пользовательского API, доступного только администратору, с использованием
имени пользователя, пароля и роли. Пользователи OIDC подключаются через настроенный вход в систему. См.
[Аутентификация](/docs/v1.0/authentication) для сопоставления и разделения учетных записей. Не делайте вывод о действии
редактирования пользователя по наличию редактируемого профиля на вашей странице настроек.

Действие удаления доступно другим пользователям и выполняется немедленно; просмотрите учетную запись, прежде чем выбрать
ее. Вы не можете удалить свою учетную запись через этот API или экран. Удаление пользователя Repovio удаляет локальный
доступ; он не удаляет учетные записи провайдера по адресу GitHub, GitLab, Forgejo или Gitea. Перед удалением проверьте
доступ затронутого пользователя.

<a id="user-mcp-tokens"></a>

## Токены пользователя MCP

Откройте диалоговое окно токена MCP пользователя, чтобы просмотреть метаданные токена или отозвать токен с
подтверждением. Администраторы не могут получать значения токена в виде открытого текста или создавать токен другого
пользователя через это диалоговое окно. Пользователи создают свои собственные токены в [Настройки MCP](/docs/v1.0/mcp).
Пустые списки и ошибки загрузки различимы; повторите попытку после восстановления API. Никогда не копируйте значения
токенов в отчеты поддержки или снимки экрана.

<a id="local-user-api"></a>

## Предоставление локального пользователя через API

Используйте клиент API через HTTPS для отправки `POST /api/v1/users` с аутентификацией носителя администратора и
`Content-Type: application/json`. Укажите это тело запроса, заменив заполнители в защищенных входных данных клиента:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

Допустимые роли: `VIEWER`, `MANAGER` и `SYSTEM_ADMIN`. Назначьте только необходимую роль, а затем отдельно предоставьте
членство в репозитории. Ответ содержит безопасные метаданные пользователя, а не пароль или его хеш. Повторяющееся имя
пользователя или неверный запрос необходимо исправить перед повторной попыткой. Не храните пароли или токены-носители в
отслеживаемых файлах, истории оболочки, снимках экрана или отчетах о проблемах.
