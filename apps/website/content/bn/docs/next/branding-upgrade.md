এই নাম পরিবর্তন একটি ব্রেকিং কনফিগারেশন পরিবর্তন. `REPOVIO_ENV_FILE`, `REPOVIO_VERSION`, `REPOVIO_API_PORT` এবং
`REPOVIO_WEB_PORT` সহ `REPOVIO_` উপসর্গে প্রতিটি প্রাক্তন পণ্য-প্রিফিক্সড পরিবেশ পরিবর্তনশীল আপডেট করুন।
`ghcr.io/repovio/repovio-api` এবং `ghcr.io/repovio/repovio-web` এর অধীনে API এবং ওয়েব ছবি ব্যবহার করুন।

আগে পূর্বের PostgreSQL 17 রিলিজে ব্র্যান্ডের নাম পরিবর্তন শেষ করুন। বর্তমান Compose কনফিগারেশন PostgreSQL 18-এর জন্য;
ব্যবহারের আগে [পৃথক PostgreSQL 18 আপগ্রেড](/docs/next/postgresql-18-upgrade) করুন। PostgreSQL 17 ফাইল কখনো PostgreSQL 18
সেবায় মাউন্ট করবেন না। নিচের ধাপগুলো সংরক্ষিত PostgreSQL 17 কনফিগারেশন, তার `compose.yml` ও `compose.upgrade.yml`
ব্যবহার করে। শুধু নাম পরিবর্তনে ডেটা রূপান্তর লাগে না; প্রধান সংস্করণ আপগ্রেড আলাদা কাজ।

## PostgreSQL ডেটা সংরক্ষণ করুন

1. বিদ্যমান ডাটাবেস ব্যাক আপ করুন এবং নিশ্চিত করুন যে স্থাপনা পরিবর্তন করার আগে ব্যাকআপ পুনরুদ্ধার করা যেতে পারে।
2. `docker inspect <postgres-container>` দিয়ে চলমান PostgreSQL কন্টেইনারটি পরিদর্শন করুন এবং `/var/lib/postgresql/data`
   এ মাউন্ট করা সঠিক নামযুক্ত ভলিউম রেকর্ড করুন। ভলিউম মুছে ফেলা ছাড়া পুরানো অ্যাপ্লিকেশন এবং PostgreSQL পাত্রে বন্ধ
   করুন।
3. নতুন স্থাপনার পরিবেশে `REPOVIO_POSTGRES_VOLUME` সেই সঠিক ভলিউম নামে সেট করুন।
   `docker volume inspect <recorded-volume>` ব্যবহার করে এটি বিদ্যমান রয়েছে তা নিশ্চিত করুন। নতুন-ইনস্টলেশন ডিফল্ট হল
   `repovio-postgres`; এটি ভুলবশত একটি বিদ্যমান ইনস্টলেশনের ভলিউম প্রতিস্থাপন করা উচিত নয়।
4. `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `TOKEN_ENCRYPTION_KEY` এবং `AUTH_JWT_SECRET` অপরিবর্তিত রাখুন।
   একই প্রধান সংস্করণে PostgreSQL রাখুন। শুরু করার আগে ব্যক্তিগতভাবে `docker compose config` পর্যালোচনা করুন; এর আউটপুটে
   সমাধান করা গোপনীয়তা রয়েছে এবং কখনই ভাগ করা বা প্রতিশ্রুতিবদ্ধ করা উচিত নয়।
5. আপগ্রেডের জন্য `docker compose -f compose.yml -f compose.upgrade.yml` ব্যবহার করুন৷ এই ওভাররাইডের জন্য নামযুক্ত ভলিউম
   বিদ্যমান থাকা প্রয়োজন, তাই একটি ভুল বানান ভলিউম নিঃশব্দে একটি খালি প্রতিস্থাপন শুরু করতে পারে না। প্রথমে PostgreSQL
   শুরু করুন এবং বিদ্যমান ডাটাবেস যাচাই করুন, তারপর মাইগ্রেশন পরিষেবা এবং অ্যাপ্লিকেশন শুরু করুন।
   `docker compose down --volumes` চালাবেন না, পুরানো ভলিউম সরান, বা এই নাম পরিবর্তনের অংশ হিসাবে একটি ফাঁকা ডাটাবেস
   আরম্ভ করবেন না।

ব্র্যান্ডিং দ্বারা কোন তথ্য রূপান্তর প্রয়োজন হয় না. ডাটাবেস শংসাপত্র এবং এনক্রিপশন কী বিদ্যমান ডেটা পড়ার জন্য
অপরিহার্য। পূর্ববর্তী স্থাপনার কনফিগারেশন এবং রক্ষিত ভলিউম ব্যবহার করে পুনরুদ্ধার করা যেতে পারে; সমসাময়িক লেখকদের
এড়িয়ে চলুন।

## প্রমাণীকরণ এবং ব্রাউজারের অবস্থা

ডিফল্ট JWT ইস্যুকারী এখন `repovio`; আপগ্রেড করার পরে আবার সাইন ইন করুন। একটি স্পষ্টভাবে কনফিগার করা ইস্যুকারীকে অবশ্যই
ইচ্ছাকৃতভাবে আপডেট করতে হবে। বিদ্যমান ব্রাউজার পছন্দ, বিজ্ঞপ্তি অবস্থা, কুকিজ এবং স্টোরেজ কী আমদানি করা হয় না। আবার
আপনার ভাষা/থিম নির্বাচন করুন, প্রয়োজনে PWA পুনরায় ইনস্টল করুন এবং ব্রাউজার বিজ্ঞপ্তি পুনরায় সক্রিয় করুন।
পরিচয়-প্রদানকারীর ডিসপ্লে নাম এবং বাহ্যিক অ্যাপ্লিকেশন কনফিগারেশন যেখানে উপযুক্ত সেখানে আপডেট করুন; কলব্যাক রুট
পরিবর্তন হয় না. নতুন ইনস্টলেশন কাজ নিশ্চিত করার পরেই অপ্রচলিত সাইট ডেটা সাফ করুন।

পূর্ববর্তী MCP টোকেনগুলি প্রত্যাহার করুন এবং প্রতিস্থাপনগুলি তৈরি করুন: পুনঃনামকৃত টোকেন উপসর্গটি ইচ্ছাকৃতভাবে একটি
উপনাম হিসাবে গৃহীত হয় না৷
