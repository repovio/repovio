## অ্যাক্সেস এবং প্রদানকারী সমর্থন

**ওভারভিউ → সিকিউরিটি অ্যালার্ট → কোড স্ক্যানিং অ্যালার্ট** খুলুন। পরিচালকদের সংগ্রহস্থলে ব্যবস্থাপনা অ্যাক্সেস
প্রয়োজন; সিস্টেম অ্যাডমিনিস্ট্রেটররা সমস্ত সংগ্রহস্থল পরিদর্শন করতে পারেন। দর্শকরা সতর্কতা ডেটা অ্যাক্সেস করতে পারে না।
তালিকা, ফিল্টার বিকল্প, কাউন্টার, বিবরণ, সংগ্রহস্থল কার্যকলাপ, এবং ড্যাশবোর্ড মেট্রিক্স একই অ্যাক্সেস সীমাবদ্ধতা প্রয়োগ
করে।

GitHub এর নিরাপত্তা API-এর মাধ্যমে এই সতর্কতার ধরন সমর্থন করে। GitLab মানচিত্র নির্ভরতা স্ক্যানিং, SAST, এবং গোপন
সনাক্তকরণ দুর্বলতাগুলি সংশ্লিষ্ট সতর্কতা দৃষ্টিভঙ্গির জন্য, উদাহরণ/লাইসেন্স এবং টোকেন অনুমতি সাপেক্ষে। Forgejo এবং Gitea
বর্তমানে এই ধরনের অসমর্থিত হিসাবে রিপোর্ট করে। একটি অনুপলব্ধ প্রকারের জন্য একটি সতর্কতা অন্যান্য সিঙ্ক্রোনাইজেশন
স্কোপগুলিকে ব্যর্থ করে না।

## ফলাফল পর্যালোচনা করুন

অনুসন্ধান এবং উপলব্ধ সংগ্রহস্থল, প্রদানকারী, তীব্রতা, এবং রাষ্ট্র ফিল্টার, বাছাই, দৃশ্যমান কলাম, এবং পৃষ্ঠা সংখ্যা
ব্যবহার করুন। রাজ্যগুলির মধ্যে রয়েছে `OPEN`, `RESOLVED`, এবং `DISMISSED`; তীব্রতা সমালোচনামূলক, উচ্চ, মাঝারি, নিম্ন,
তথ্যগত, এবং অজানা অন্তর্ভুক্ত। কোড ফিল্টারগুলি অতিরিক্তভাবে স্ক্যানার, নিয়ম এবং একটি ডেডিকেটেড ফাইল-পাথ নির্বাচক
অন্তর্ভুক্ত করে। হালনাগাদ-তারিখের সীমা এবং ধরনের-নির্দিষ্ট পাঠ্য অনুসন্ধান বড় তালিকাকে সংকীর্ণ করতে সহায়তা করে।
স্ক্যানার, নিয়ম, তীব্রতা, নিরাপদ ফাইলের অবস্থান এবং খোঁজার অবস্থা পরিদর্শন করার জন্য একটি অনুসন্ধান নির্বাচন করুন।
Repovio শুধুমাত্র অনুমোদিত মেটাডেটা স্টোর করে; কাঁচা প্রদানকারীর পেলোড, শংসাপত্র, টোকেন টুকরা এবং গোপন মানগুলি কখনই ধরে
রাখা হয় না। অনুপস্থিত ক্ষেত্রগুলি একটি প্রক্রিয়াকরণ ত্রুটির পরিবর্তে প্রদানকারীর ক্ষমতা প্রতিফলিত করতে পারে।

তদন্ত ও প্রতিকার করতে **প্রদানকারীতে খুলুন** ব্যবহার করুন। Repovio সতর্কতাগুলি খারিজ, সমাধান, পুনরায় খুলতে বা সম্পাদনা
করে না। রিপোজিটরি প্রতি প্রথম সফল পঠন এবং সতর্কতা ধরনের একটি নীরব বেসলাইন স্থাপন করে। পরে খোলা, সমাধান করা, বরখাস্ত করা
বা পুনরায় খোলা ট্রানজিশন সদস্যতা [বিজ্ঞপ্তি চ্যানেল](/docs/v2.0/notifications) ট্রিগার করতে পারে।

## খালি, অনুপলব্ধ এবং বাসি ডেটা

ফিল্টারগুলি সাফ করুন এবং যদি কোনও অনুসন্ধান না পাওয়া যায় তবে পরিচালনার সদস্যতা যাচাই করুন। অসমর্থিত ধরণের বা অনুমতি
সতর্কতার জন্য [সিঙ্ক্রোনাইজেশন কাজ](/docs/v2.0/guide-jobs) পরিদর্শন করুন। বিদ্যমান GitHub OAuth অ্যাকাউন্টগুলির
`security_events` এর সাথে পুনরায় অনুমোদনের প্রয়োজন হতে পারে; [প্রদানকারী OAuth](/docs/v2.0/provider-oauth) দেখুন।
পুনরুদ্ধারের পরে ব্যর্থ লোড পুনরায় চেষ্টা করুন; দৃশ্যমান ফলাফলের অনুপস্থিতি প্রমাণ নয় যে প্রদানকারী সংগ্রহস্থল স্ক্যান
করেছে বা প্রতিটি সতর্কতা প্রকার সমর্থিত।
