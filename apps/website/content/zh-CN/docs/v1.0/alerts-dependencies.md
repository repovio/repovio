<a id="access-and-provider-support"></a>

## 访问和提供商支持

打开**概述 → 安全警报 → 依赖项警报**。管理人员需要对存储库进行管理访问；系统管理员可以检查所有存储库。查看者无法访问警报数据。列表、筛选器选项、计数器、详细信息、存储库活动和仪表板指标应用相同的访问限制。

GitHub 通过其安全 API 支持此警报类型。 GitLab 将依赖项扫描、SAST 和秘密检测漏洞映射到相应的警报视图，具体取决于实例/许可证和令牌权限。 Forgejo 和 Gitea 目前报告这些类型不受支持。不可用类型的警告不会导致其他同步范围失败。

<a id="review-findings"></a>

## 审查结果

使用搜索和可用存储库、提供程序、严重性和状态过滤器、排序、可见列和分页。状态包括 `OPEN`、`RESOLVED` 和
`DISMISSED`；严重性包括严重、高、中、低、信息和未知。依赖过滤器还包括生态系统、包和清单。更新日期范围和特定于种类的文本搜索有助于缩小大型列表的范围。选择一个结果来检查包名称、生态系统、严重性、漏洞元数据和受影响的依赖项位置。 Repovio 仅存储列入许可名单的元数据；原始提供者有效负载、凭证、令牌片段和秘密值永远不会保留。缺失字段可以反映提供商的能力，而不是处理错误。

使用**在提供程序中打开**来调查和修复。 Repovio 不会消除、解决、重新打开或编辑警报。每个存储库和警报类型的第一次成功读取建立了静默基线。稍后打开、解决、取消或重新打开的转换可以触发订阅的
[通知渠道](/docs/v1.0/notifications)。

<a id="empty-unavailable-and-stale-data"></a>

## 空的、不可用的和过时的数据

如果没有发现任何结果，请清除过滤器并验证管理成员资格。检查 [同步任务](/docs/v1.0/guide-jobs)
是否有不支持的类型或权限警告。现有的 GitHub OAuth 账户可能需要使用 `security_events` 重新授权；参见
[提供商 OAuth](/docs/v1.0/provider-oauth)。恢复后重试失败的加载；没有可见的发现并不能证明提供商已扫描存储库或支持每种警报类型。
