Это переименование является критическим изменением конфигурации. Обновите все префиксы среды с префиксом продукта до
префикса `REPOVIO_`, включая `REPOVIO_ENV_FILE`, `REPOVIO_VERSION`, `REPOVIO_API_PORT` и `REPOVIO_WEB_PORT`. Используйте
API и веб-образы под `ghcr.io/repovio/repovio-api` и `ghcr.io/repovio/repovio-web`.

Сначала завершите переименование на предыдущем выпуске с PostgreSQL 17. Текущая конфигурация Compose использует
PostgreSQL 18; до её использования выполните [отдельное обновление PostgreSQL 18](/docs/next/postgresql-18-upgrade).
Никогда не монтируйте файлы PostgreSQL 17 в сервис PostgreSQL 18. Ниже используется сохранённая конфигурация PostgreSQL
17, включая `compose.yml` и `compose.upgrade.yml`. Само переименование не требует преобразования данных; смена основной
версии — отдельная операция.

## Сохранить данные PostgreSQL

1. Создайте резервную копию существующей базы данных и убедитесь, что резервную копию можно восстановить, прежде чем
   менять развертывание.
2. Проверьте работающий контейнер PostgreSQL с `docker inspect <postgres-container>` и запишите точное имя тома,
   смонтированного в `/var/lib/postgresql/data`. Остановите старое приложение и контейнеры PostgreSQL, не удаляя тома.
3. Установите для `REPOVIO_POSTGRES_VOLUME` в новой среде развертывания именно это имя тома. Подтвердите его
   существование, используя `docker volume inspect <recorded-volume>`. Значение по умолчанию для новой установки —
   `repovio-postgres`; он не должен случайно заменять том существующей установки.
4. Оставьте `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `TOKEN_ENCRYPTION_KEY` и `AUTH_JWT_SECRET` без
   изменений. Оставьте PostgreSQL той же основной версии. Перед началом работы просмотрите `docker compose config`
   лично; его выходные данные содержат разрешенные секреты и никогда не должны передаваться или фиксироваться.
5. Используйте `docker compose -f compose.yml -f compose.upgrade.yml` для обновления. Для этого переопределения
   необходимо, чтобы указанный том существовал, поэтому том с ошибкой не может автоматически инициализировать пустую
   замену. Сначала запустите PostgreSQL и проверьте существующую базу данных, затем запустите службу миграции и
   приложение. Никогда не запускайте `docker compose down --volumes`, не удаляйте старый том и не инициализируйте пустую
   базу данных в рамках этого переименования.

Для брендинга преобразование данных не требуется. Учетные данные базы данных и ключ шифрования по-прежнему необходимы
для чтения существующих данных. Предыдущее развертывание можно восстановить, используя его конфигурацию и сохраненный
том; избегайте одновременных авторов.

## Аутентификация и состояние браузера

Издателем JWT по умолчанию теперь является `repovio`; войдите в систему еще раз после обновления. Явно настроенный
издатель также должен быть обновлен намеренно. Существующие настройки браузера, состояние уведомлений, файлы cookie и
ключи хранения не импортируются. Снова выберите язык/тему, при необходимости переустановите PWA и снова включите
уведомления браузера. При необходимости обновить отображаемые имена поставщика удостоверений и конфигурацию внешнего
приложения; маршруты обратного вызова не меняются. Удалите устаревшие данные сайта только после подтверждения работы
новой установки.

Отозвать предыдущие токены MCP и создать замены: переименованный префикс токена намеренно не принимается в качестве
псевдонима.
