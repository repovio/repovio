> アーカイブされたソース スナップショット。製品ラベルはRepovioを使用します。このリリースのタグ付きデプロイメント ファイルの構成識別子とコンテナー参照を変更せずに使用します。

Repovio は、ステートレス モデル コンテキスト プロトコル エンドポイントを `/mcp`
で公開します。これは、認証されたユーザーが Repovio で確認できるのと同じリポジトリ、ワークフロー実行、失敗キュー、承認キュー、概要、および傾向への読み取り専用アクセスを提供します。

MCP サーバーは、ローカル Repovio データベースを読み取ります。プロバイダーの変更 API の呼び出し、同期の開始、ワークフローの承認、Repovio 構成の変更は行いません。

<a id="create-an-access-token"></a>

## アクセストークンを作成する

**設定**を開き、**MCP アクセス**
タブを選択して、名前付きトークンを作成します。有効期限はオプションです。 Repovio はトークンを 1 回だけ表示し、その SHA-256 ハッシュのみを保存するため、作成ダイアログから完全なトークンをコピーします。

トークンの取り消しは、次のリクエストで有効になります。ユーザーを削除すると、トークンも削除されます。すべてのリクエストがデータベースからの現在の承認を解決するため、ユーザーのロールまたはリポジトリ メンバーシップへの変更はすぐに適用されます。

<a id="configure-a-client"></a>

## クライアントを構成する

パブリック Repovio オリジンの後に `/mcp` を使用し、認可ヘッダーでトークンを送信します。

```text
URL: https://repovio.example.com/mcp
Authorization: Bearer ezrepo_mcp_REPLACE_WITH_TOKEN
```

最初のリリースは、エディターやコマンドライン クライアントなど、カスタム HTTP ヘッダーをサポートする MCP クライアントをターゲットとしています。 OAuth 検出は提供されず、MCP
OAuth フローを必要とするホストとの互換性も主張しません。

URL、クエリ パラメータ、追跡された構成ファイル、シェル履歴、またはログにはトークンを決して置かないでください。クライアントのシークレット ストレージまたはバージョン管理されていない環境変数を優先します。

<a id="available-tools"></a>

## 利用可能なツール

| ツール                   | 目的                                                                        |
| ------------------------ | --------------------------------------------------------------------------- |
| `list_repositories`      | 表示可能な追跡リポジトリをリストします。                                    |
| `get_repository`         | 表示されている 1 つの追跡リポジトリを読み取ります。                         |
| `list_workflow_runs`     | クエリ正規化された可視ワークフローが実行されます。                          |
| `list_needs_attention`   | 最新のターミナルの実行が失敗したワークフロー コンテキストを一覧表示します。 |
| `list_awaiting_approval` | プロバイダーの承認を待っている現在表示されている実行をリストします。        |
| `get_dashboard_summary`  | 包括的な時間範囲における目に見えるワークフローの健全性を要約します。        |
| `get_workflow_trend`     | 目に見える成功と失敗の傾向バケットを集計します。                            |

リスト ツールのデフォルトは 1 ページあたり 25 件の結果で、最大 100 件を受け入れます。ツールの出力には、構造化された JSON と一致するテキスト表現が含まれます。日付には ISO
8601 UTC 値が使用されます。

サーバーは、MCP リソース、プロンプト、タスク、サブスクリプション、プロバイダー アクション、または構成ツールを意図的にアドバタイズしません。

<a id="reverse-proxy-requirements"></a>

## リバースプロキシ要件

- `POST /mcp`を`/api/v1/mcp`に書き換えずにAPIコンテナに転送します。
- `Authorization`、`Origin`、`Content-Type`、`Accept`、`MCP-Protocol-Version`、`Mcp-Method`、および`Mcp-Name`を転送します。
- リバース プロキシで TLS を使用し、認証ヘッダーやリクエスト クエリ文字列をログに記録しません。
- 許可されているすべてのブラウザーのオリジンを `CORS_ORIGIN` に追加します。 `Origin`
  ヘッダーのないリクエストは、ネイティブ クライアントに対して引き続きサポートされます。現在のオリジンは、設定された許可リストと一致する必要があります。

<a id="token-administration"></a>

## トークン管理

ユーザーは、[設定] の [**MCP アクセス**] タブで自分のトークンを管理します。システム管理者は、安全なトークンのメタデータを検査し、「ユーザー」ページからトークンを取り消すことができますが、そのハッシュまたはプレーンテキストのシークレットを取得したり、別のユーザーに代わってトークンを作成したりすることはできません。

<a id="manage-token-states"></a>

## トークンの状態を管理する

トークン リストには、名前、ステータス、安全なプレフィックス、作成/最後に使用されたタイムスタンプ、およびオプションの有効期限が表示されます。名前には最大 100 文字を含めることができます。取り消しには確認が必要です。取り消されたトークンまたは期限切れのトークンは、今後のリクエストを認証できません。空のリストは、ユーザーのトークンが存在しないことを意味します。ロードエラーの場合は再試行が必要です。 1 回限りの表示を閉じる前に、新しいトークン全体をコピーします。管理者トークン ダイアログでは、リスト/取り消しのみが許可され、別のユーザーの作成は許可されません。
