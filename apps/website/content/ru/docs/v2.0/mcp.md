Repovio предоставляет конечную точку протокола контекста модели без сохранения состояния по адресу `/mcp`. Он
обеспечивает доступ только для чтения к тем же репозиториям, запускам рабочих процессов, очередям ошибок, очередям
утверждений, сводкам и тенденциям, которые аутентифицированный пользователь может видеть в Repovio.

Сервер MCP считывает локальную базу данных Repovio. Он не вызывает API-интерфейсы мутации поставщика, не запускает
синхронизацию, не утверждает рабочие процессы и не изменяет конфигурацию Repovio.

<a id="create-an-access-token"></a>

## Создайте токен доступа

Откройте **Настройки**, выберите вкладку**Доступ MCP** и создайте именованный токен. Срок действия не является
обязательным. Скопируйте полный токен из диалогового окна создания, поскольку Repovio отображает его только один раз и
сохраняет только его хэш SHA-256.

Отзыв токена вступит в силу при следующем запросе. Удаление пользователя также удаляет токен. Изменения роли
пользователя или членства в репозитории применяются немедленно, поскольку каждый запрос разрешает текущую авторизацию из
базы данных.

<a id="configure-a-client"></a>

## Настройка клиента

Используйте общедоступный источник Repovio, за которым следует `/mcp`, и отправьте токен в заголовке авторизации:

```text
URL: https://repovio.example.com/mcp
Authorization: Bearer repovio_mcp_REPLACE_WITH_TOKEN
```

Первый выпуск предназначен для клиентов MCP, поддерживающих пользовательские заголовки HTTP, таких как клиенты редактора
и командной строки. Он не обеспечивает обнаружение OAuth и не заявляет о совместимости с хостами, которым требуется
поток MCP OAuth.

Никогда не размещайте токен в URL-адресе, параметре запроса, отслеживаемом файле конфигурации, истории оболочки или
журнале. Предпочитайте секретное хранилище клиента или неверсированную переменную среды.

<a id="available-tools"></a>

## Доступные инструменты

| Инструмент               | Цель                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `list_repositories`      | Список видимых отслеживаемых репозиториев.                                                   |
| `get_repository`         | Прочитайте один видимый отслеживаемый репозиторий.                                           |
| `list_workflow_runs`     | Запрос нормализует видимый рабочий процесс.                                                  |
| `list_needs_attention`   | Список контекстов рабочих процессов, последний запуск терминала которых завершился неудачей. |
| `list_awaiting_approval` | Список текущих видимых запусков, ожидающих одобрения поставщика.                             |
| `get_dashboard_summary`  | Подведите итоги видимого состояния рабочего процесса за полный диапазон времени.             |
| `get_workflow_trend`     | Объедините сегменты видимых тенденций успеха и неудач.                                       |

Инструменты создания списков по умолчанию принимают 25 результатов на страницу и принимают не более 100. Вывод
инструмента содержит структурированный JSON и соответствующее текстовое представление. В датах используются значения ISO
8601 UTC.

Сервер намеренно не рекламирует ресурсы MCP, подсказки, задачи, подписки, действия поставщика или инструменты настройки.

<a id="reverse-proxy-requirements"></a>

## Требования к обратному прокси

— Перенаправить `POST /mcp` в контейнер API, не переписывая его на `/api/v1/mcp`.

- Нападающие `Authorization`, `Origin`, `Content-Type`, `Accept`, `MCP-Protocol-Version`, `Mcp-Method` и `Mcp-Name`. —
  Используйте TLS на обратном прокси-сервере и не регистрируйте заголовки авторизации и не запрашивайте строки запроса.
- Добавьте все разрешенные источники браузера в `CORS_ORIGIN`. Запросы без заголовка `Origin` остаются поддерживаемыми
  для собственных клиентов; текущие источники должны соответствовать настроенному списку разрешений.

<a id="token-administration"></a>

## Администрирование токенов

Пользователи управляют своими токенами на вкладке **MCP доступ** в разделе «Настройки». Системные администраторы могут
проверять метаданные безопасного токена и отозвать токен со страницы «Пользователи», но не могут получить его хэш или
секретный текст и не могут создавать токен от имени другого пользователя.

<a id="manage-token-states"></a>

## Управление состояниями токенов

В списке токенов отображаются имя, статус, безопасный префикс, временные метки создания/последнего использования и
необязательный срок действия. Имена могут содержать не более 100 символов. Отзыв требует подтверждения. Отозванный или
просроченный токен не может аутентифицировать будущие запросы. Пустой список означает, что для пользователя не
существует токенов; ошибка загрузки предлагает повторить попытку. Скопируйте новый токен полностью, прежде чем закрывать
его одноразовое отображение. Диалоговые окна токенов администратора допускают только листинг/отзыв, но не создание для
другого пользователя.
