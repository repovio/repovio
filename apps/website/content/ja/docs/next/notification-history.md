<a id="review-deliveries"></a>

## 配信を確認する

**[通知] → [配信履歴]**
を開くことができるのはシステム管理者のみです。この表はイベント配信とテストを区別し、イベント タイプ、リポジトリ、サブジェクト/プロバイダー リンク、チャネル、状態、試行回数、次の試行、およびサニタイズされた最終エラーを示します。種類/ステータスでフィルターし、並べ替え、列コントロール、ページネーションを使用します。

件名、要求者（存在する場合）、チャネル、ステータス、試行ごとのタイムスタンプ、デバイス ラベル、およびエラーの配信を開きます。シークレット、生の転送先、プロバイダーの資格情報は決して返されません。ブラウザ プッシュ配信には、個別の購読済みデバイスに対する試行が含まれる場合があります。

<a id="interpret-outcomes"></a>

## 結果を解釈する

保留/再試行のタイミングは、プロバイダーのワークフロー キューではなく、永続的な配信作業を表します。試行が成功すると、トランスポートが配信を受け入れたことが確認されます。障害が発生した場合は、チャネル構成と宛先サービスを調査する必要があります。この履歴ビューには、再実行、キャンセル、または手動での再試行アクションはありません。を修正します
[チャネル](/docs/next/notifications) そして、そのテスト アクションを使用して構成を確認します。

空のテーブルにはフィルターが反映されているか、保持されない配信が反映されていない可能性があります。失敗したリスト/詳細リクエストは個別に表示されます。回復後に再試行してください。初期同期では、意図的にライフサイクル配信が行われない場合があります。サブジェクトの外部リンクは、提供せずにプロバイダー コンテキストを開きます。 Repovio 書き込みアクセス。
