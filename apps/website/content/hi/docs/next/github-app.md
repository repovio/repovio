<a id="register-app"></a>

## ऐप पंजीकृत करें

प्रत्येक Repovio परिनियोजन के लिए एक GitHub.com App रखें। PAT और OAuth उपलब्ध रहते हैं। स्वामी के रूप में Settings,
Developer settings, GitHub Apps, New GitHub App खोलें। अनूठा नाम और Repovio मुखपृष्ठ चुनें। कई खातों के लिए Any account
चुनें; निजी ऐप केवल स्वामी के खाते में लग सकता है। OAuth क्लाइंट सीक्रेट, कॉलबैक URL और सेटअप URL आवश्यक नहीं हैं।

<a id="permissions-and-events"></a>

## अनुमतियाँ और घटनाएँ

नीचे की मुख्य अनुमतियाँ Read-only रखें; Metadata स्वतः मिलता है। वैकल्पिक सुरक्षा अनुमतियाँ केवल आवश्यकता और उपलब्धता पर
जोड़ें। सूची की घटनाएँ चुनें; स्थापना जीवनचक्र घटनाएँ GitHub स्वतः भेजता है। ऐप में अधिक अनुमति होने पर भी Repovio केवल
पढ़ने वाले टोकन माँगता है।

```text
Required repository permissions (Read-only):
Actions (actions)
Issues (issues)
Pull requests (pull_requests)
Metadata (metadata, automatic)

Optional repository permissions (Read-only):
Dependabot alerts (dependabot_alerts)
Code scanning alerts (security_events)
Secret scanning alerts (secret_scanning_alerts)

Webhook events:
workflow_run
issues
pull_request
dependabot_alert
code_scanning_alert
secret_scanning_alert
```

<a id="configure-repovio"></a>

## Repovio कॉन्फ़िगर करें

वेबहुक चालू करके नीचे का सार्वजनिक HTTPS पता उपयोग करें। PUBLIC_URL बाहरी पहुँच वाले परिनियोजन पर होना चाहिए। कम से कम
16 अक्षरों का यादृच्छिक सीक्रेट बनाएँ और GitHub तथा Repovio में समान मान भरें। GitHub पर RSA कुंजी बनाकर PEM डाउनलोड
करें। प्रशासन में प्रदाता खाते, GitHub App खोलें; App ID, slug, पूरी निजी कुंजी और वेबहुक सीक्रेट भरकर सत्यापित और
सहेजें। API पहचान जाँचकर दोनों सीक्रेट PostgreSQL में एन्क्रिप्ट करता है। परिनियोजन की एन्क्रिप्शन कुंजी सुरक्षित रखें;
सहेजे सीक्रेट ब्राउज़र में नहीं लौटते।

```text
https://repovio.example.com/api/v1/webhooks/github-app
```

<a id="install-and-connect"></a>

## स्थापित करें और जोड़ें

GitHub पर ऐप लगाएँ, खाता या संगठन और केवल आवश्यक रिपॉज़िटरी चुनें। वापस आकर स्थापना सूची ताज़ा करें और खाता जोड़ें।
निलंबित या पहले से जुड़े स्थापना को दोबारा नहीं जोड़ सकते। सूची कॉन्फ़िगर किए ऐप से मिलती है; कॉलबैक की स्थापना ID
विश्वसनीय नहीं मानी जाती। रिपॉज़िटरी स्क्रीन से ट्रैकिंग जोड़ें। टोकन स्वतः नवीनीकृत होते हैं; शुरुआती आयात और नियमित
पोलिंग वेबहुक का पूरक हैं।

यदि नाम मौजूदा PAT या OAuth खाते से मिलता है, तो जोड़ने से पहले स्थानीय खाते का नाम बदलें।

<a id="rotate-and-disconnect"></a>

## बदलें और अलग करें

GitHub पर नई कुंजी बनाएँ, सहेजें और पुरानी हटाने से पहले सिंक जाँचें। वेबहुक सीक्रेट दोनों ओर साथ बदलें; पुरानी
हस्ताक्षर तुरंत अमान्य होते हैं। खाली फ़ील्ड पुराना सीक्रेट रखते हैं। ऐप पहचान बदलने या कॉन्फ़िगरेशन हटाने से पहले जुड़े
खाते हटाएँ। संबंधित ट्रैकिंग डेटा भी हटता है, इसलिए पहले निर्यात करें। स्थानीय हटाना GitHub से ऐप नहीं हटाता।

<a id="troubleshooting"></a>

## समस्या समाधान

सेटअप विफल होने पर App ID, slug और PEM जाँचें। हस्ताक्षर विफल होने पर सीक्रेट, HTTPS और प्रॉक्सी द्वारा मूल बॉडी
सुरक्षित रहने की जाँच करें। सूची खाली हो तो रिपॉज़िटरी चयन और अनुमतियाँ जाँचकर ताज़ा करें। निलंबित या हटाई स्थापना का
पुराना डेटा रहता है; GitHub पर पहुँच बहाल करके ताज़ा करें। वैकल्पिक सुरक्षा अनुमति न होने से दूसरे क्षेत्र नहीं रुकते।
Jobs देखें। वेबहुक विफल होने पर पोलिंग चलती रहती है। मॉक परीक्षण वास्तविक GitHub स्थापना सत्यापित नहीं करते; परीक्षण ऐप
चाहिए।
