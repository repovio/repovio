> لقطة المصدر المؤرشفة. تستخدم ملصقات المنتجات Repovio. استخدم معرفات التكوين ومراجع الحاوية من ملفات النشر ذات العلامات
> لهذا الإصدار دون تغيير.

<a id="review-accounts"></a>

## مراجعة الحسابات

يفتح مسؤولو النظام **الإدارة → المستخدمين**. يعرض الجدول اسم المستخدم، والصورة الرمزية/اسم العرض، والدور، والأصل
المحلي/OIDC، والطوابع الزمنية التي تم إنشاؤها/تحديثها. قم بالتصفية حسب الدور أو الفرز أو تغيير الأعمدة أو ترقيم الصفحات.
يتطلب الوصول إلى المستودع للعارض أو المدير [عضوية المستودع](/docs/v1.0/repositories) منفصلاً؛ لا تقوم مجموعات موفري
الهوية بإنشاء تلك العضويات.

<a id="provisioning-and-deletion"></a>

## التزويد والحذف

لا تحتوي صفحة المستخدمين على نموذج إنشاء مستخدم أو تعديل مستخدم. يتم إنشاء مستخدمين محليين إضافيين من خلال واجهة برمجة
تطبيقات المستخدم المحمية للمسؤول فقط باستخدام اسم المستخدم وكلمة المرور والدور. يتم توفير مستخدمي OIDC من خلال تسجيل
الدخول بالهوية المكونة. راجع [المصادقة](/docs/v1.0/authentication) للتخطيط وفصل الحساب. لا تستنتج إجراء تحرير المستخدم
من خلال وجود ملف تعريف قابل للتحرير في صفحة الإعدادات الخاصة بك.

إجراء الحذف متاح للمستخدمين الآخرين ويتم تنفيذه على الفور؛ قم بمراجعة الحساب قبل اختياره. لا يمكنك حذف حسابك الخاص من
خلال واجهة برمجة التطبيقات هذه أو الشاشة. يؤدي حذف مستخدم Repovio إلى إزالة الوصول المحلي؛ ولا يحذف أي حساب موفر على
GitHub أو GitLab أو Forgejo أو Gitea. قم بمراجعة وصول المستخدم المتأثر قبل الحذف.

<a id="user-mcp-tokens"></a>

## الرموز المميزة للمستخدم MCP

افتح مربع حوار الرمز المميز MCP الخاص بالمستخدم لسرد بيانات تعريف الرمز المميز أو إلغاء الرمز المميز مع التأكيد. لا يمكن
للمسؤولين استرداد قيم الرمز المميز للنص العادي أو إنشاء رمز مميز لمستخدم آخر من خلال مربع الحوار هذا. يقوم المستخدمون
بإنشاء الرموز المميزة الخاصة بهم في [إعدادات MCP](/docs/v1.0/mcp). تختلف القوائم الفارغة عن أخطاء التحميل؛ أعد المحاولة
بعد استرداد API. لا تقم مطلقًا بنسخ قيم الرموز المميزة في تقارير الدعم أو لقطات الشاشة.

<a id="local-user-api"></a>

## توفير مستخدم محلي من خلال واجهة برمجة التطبيقات

استخدم عميل API عبر HTTPS لإرسال `POST /api/v1/users` مع مصادقة حامل المسؤول و`Content-Type: application/json`. قم
بتوفير نص الطلب هذا، مع استبدال العناصر النائبة في المدخلات المحمية للعميل:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

الأدوار الصالحة هي `VIEWER`، و`MANAGER`، و`SYSTEM_ADMIN`. قم بتعيين الدور المطلوب فقط، ثم قم بمنح عضويات المستودع بشكل
منفصل. تحتوي الاستجابة على بيانات تعريف آمنة للمستخدم، وليس كلمة المرور أو التجزئة الخاصة بها. يجب تصحيح اسم المستخدم
المكرر أو الطلب غير الصالح قبل إعادة المحاولة. لا تقم بتخزين كلمات المرور أو الرموز المميزة لحاملها في الملفات المتعقبة
أو سجل الصدفة أو لقطات الشاشة أو تقارير الإصدار.
