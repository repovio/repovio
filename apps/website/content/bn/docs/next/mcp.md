Repovio `/mcp` এ একটি স্টেটলেস মডেল কনটেক্সট প্রোটোকল এন্ডপয়েন্ট প্রকাশ করে। এটি একই রিপোজিটরি, ওয়ার্কফ্লো রান,
ব্যর্থতার সারি, অনুমোদন সারি, সারাংশ এবং প্রবণতা যা প্রমাণীকৃত ব্যবহারকারী Repovio-এ দেখতে পারে সেগুলিতে শুধুমাত্র
পঠনযোগ্য অ্যাক্সেস প্রদান করে।

MCP সার্ভার স্থানীয় Repovio ডাটাবেস পড়ে। এটি প্রদানকারী মিউটেশন API কল করে না, সিঙ্ক্রোনাইজেশন শুরু করে, ওয়ার্কফ্লো
অনুমোদন করে, বা Repovio কনফিগারেশন পরিবর্তন করে না।

একই `/mcp` এন্ডপয়েন্ট Codex-এর মতো পুরোনো ক্লায়েন্টের `2025-06-18` প্রোটোকল এবং আধুনিক `2026-07-28` প্রোটোকল সমর্থন করে।
পুরোনো ক্লায়েন্ট প্রথমে `initialize`, তারপর `notifications/initialized` পাঠায়; আধুনিক ক্লায়েন্ট প্রতিটি অনুরোধে প্রোটোকলের মেটাডেটা পাঠায়।
উভয়েই একই সাতটি শুধু পড়ার টুল প্রদান করে এবং বর্তমান ব্যবহারকারীর Bearer টোকেন দিয়ে প্রতিটি অনুরোধ যাচাই করে।
প্রতিটি অনুরোধের জন্য নতুন সার্ভার ইনস্ট্যান্স ব্যবহৃত হয়; স্থায়ী MCP সেশন রাখা হয় না।

## একটি অ্যাক্সেস টোকেন তৈরি করুন

**সেটিংস** খুলুন,**MCP অ্যাক্সেস** ট্যাবটি নির্বাচন করুন এবং একটি নামযুক্ত টোকেন তৈরি করুন৷ মেয়াদ শেষ হওয়া ঐচ্ছিক।
নির্মাণ ডায়ালগ থেকে সম্পূর্ণ টোকেনটি অনুলিপি করুন কারণ Repovio এটি শুধুমাত্র একবার প্রদর্শন করে এবং শুধুমাত্র এর
SHA-256 হ্যাশ সংরক্ষণ করে।

একটি টোকেন প্রত্যাহার করা পরবর্তী অনুরোধে কার্যকর হয়। এর ব্যবহারকারীকে মুছে দিলেও টোকেন মুছে যায়। ব্যবহারকারীর ভূমিকা
বা সংগ্রহস্থল সদস্যপদ পরিবর্তন অবিলম্বে প্রযোজ্য কারণ প্রতিটি অনুরোধ ডাটাবেস থেকে বর্তমান অনুমোদনের সমাধান করে।

<a id="configure-a-client"></a>

## একটি ক্লায়েন্ট কনফিগার করুন

সর্বজনীন Repovio অরিজিন ব্যবহার করুন এবং `/mcp` অনুসরণ করুন এবং অনুমোদনের শিরোনামে টোকেন পাঠান:

```text
URL: https://repovio.example.com/mcp
Authorization: Bearer repovio_mcp_REPLACE_WITH_TOKEN
```

প্রথম রিলিজ MCP ক্লায়েন্টদের লক্ষ্য করে যারা কাস্টম HTTP হেডার সমর্থন করে, যেমন সম্পাদক এবং কমান্ড-লাইন ক্লায়েন্ট। এটি
OAuth আবিষ্কার প্রদান করে না এবং MCP OAuth প্রবাহের প্রয়োজন হয় এমন হোস্টগুলির সাথে সামঞ্জস্যতা দাবি করে না।

ইউআরএল, ক্যোয়ারী প্যারামিটার, ট্র্যাক করা কনফিগারেশন ফাইল, শেল ইতিহাস বা লগে টোকেন রাখবেন না। ক্লায়েন্টের গোপন স্টোরেজ
বা একটি পরিবর্তনবিহীন পরিবেশ পরিবর্তনশীল পছন্দ করুন।

<a id="available-tools"></a>

## উপলব্ধ সরঞ্জাম

| টুল                      | উদ্দেশ্য                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------- |
| `list_repositories`      | দৃশ্যমান ট্র্যাক করা সংগ্রহস্থল তালিকা.                                            |
| `get_repository`         | একটি দৃশ্যমান ট্র্যাক করা সংগ্রহস্থল পড়ুন।                                        |
| `list_workflow_runs`     | প্রশ্ন স্বাভাবিক দৃশ্যমান কর্মপ্রবাহ রান.                                          |
| `list_needs_attention`   | ওয়ার্কফ্লো প্রসঙ্গ তালিকা করুন যার নতুন টার্মিনাল রান ব্যর্থ হয়েছে।              |
| `list_awaiting_approval` | প্রদানকারীর অনুমোদনের জন্য অপেক্ষা করা বর্তমান দৃশ্যমান রানের তালিকা করুন।         |
| `get_dashboard_summary`  | একটি অন্তর্ভূক্ত সময়ের পরিসরের জন্য দৃশ্যমান কর্মপ্রবাহের স্বাস্থ্যের সারসংক্ষেপ। |
| `get_workflow_trend`     | মোট দৃশ্যমান সাফল্য এবং ব্যর্থতার প্রবণতা বালতি।                                   |

প্রতি পৃষ্ঠায় 25টি ফলাফলের জন্য ডিফল্ট সরঞ্জামগুলি তালিকাভুক্ত করুন এবং সর্বাধিক 100টি গ্রহণ করুন৷ টুল আউটপুটে কাঠামোগত
JSON এবং একটি মিলে যাওয়া পাঠ্য উপস্থাপনা রয়েছে৷ তারিখগুলি ISO 8601 UTC মান ব্যবহার করে।

সার্ভার ইচ্ছাকৃতভাবে কোন MCP সম্পদ, প্রম্পট, কাজ, সদস্যতা, প্রদানকারীর ক্রিয়া বা কনফিগারেশন টুলের বিজ্ঞাপন দেয় না।

<a id="reverse-proxy-requirements"></a>

## বিপরীত প্রক্সি প্রয়োজনীয়তা

- `POST /mcp` কে `/api/v1/mcp` এ পুনরায় না লিখে এপিআই কন্টেইনারে ফরওয়ার্ড করুন।
- `Authorization`, `Origin`, `Content-Type`, `Accept`, `MCP-Protocol-Version`, `Mcp-Method`, এবং `Mcp-Name` ফরোয়ার্ড
  করুন।
- বিপরীত প্রক্সিতে TLS ব্যবহার করুন এবং অনুমোদনের শিরোনাম লগ করবেন না বা ক্যোয়ারী স্ট্রিং অনুরোধ করবেন না।
- `CORS_ORIGIN`-এ প্রতিটি অনুমোদিত ব্রাউজার অরিজিন যোগ করুন। একটি `Origin` শিরোনাম ছাড়া অনুরোধ নেটিভ ক্লায়েন্টদের জন্য
  সমর্থিত থাকে; বর্তমান উত্স অবশ্যই কনফিগার করা অনুমোদিত তালিকার সাথে মিলবে৷

<a id="token-administration"></a>

## টোকেন প্রশাসন

ব্যবহারকারীরা সেটিংসের অধীনে **MCP অ্যাক্সেস** ট্যাবে তাদের নিজস্ব টোকেনগুলি পরিচালনা করে৷ সিস্টেম অ্যাডমিনিস্ট্রেটররা
নিরাপদ টোকেন মেটাডেটা পরিদর্শন করতে পারে এবং ব্যবহারকারীদের পৃষ্ঠা থেকে একটি টোকেন প্রত্যাহার করতে পারে, কিন্তু এর হ্যাশ
বা প্লেইনটেক্সট গোপন পুনরুদ্ধার করতে পারে না এবং অন্য ব্যবহারকারীর পক্ষে একটি টোকেন তৈরি করতে পারে না।

<a id="manage-token-states"></a>

## টোকেন স্টেট ম্যানেজ করুন

টোকেন তালিকা নাম, স্থিতি, নিরাপদ উপসর্গ, তৈরি/শেষ-ব্যবহৃত টাইমস্ট্যাম্প এবং ঐচ্ছিক মেয়াদ দেখায়। নামগুলিতে সর্বাধিক
100টি অক্ষর থাকতে পারে। প্রত্যাহার নিশ্চিতকরণ প্রয়োজন. একটি প্রত্যাহার বা মেয়াদোত্তীর্ণ টোকেন ভবিষ্যতের অনুরোধগুলিকে
প্রমাণীকরণ করতে পারে না। একটি খালি তালিকা মানে ব্যবহারকারীর জন্য কোন টোকেন বিদ্যমান নেই; একটি লোড ত্রুটি পুনরায় চেষ্টা
করার প্রস্তাব দেয়। এককালীন প্রদর্শন বন্ধ করার আগে সম্পূর্ণ নতুন টোকেনটি অনুলিপি করুন। অ্যাডমিনিস্ট্রেটর টোকেন ডায়ালগ
শুধুমাত্র তালিকা/প্রত্যাহার করার অনুমতি দেয়, অন্য ব্যবহারকারীর জন্য কখনই তৈরি করে না।
