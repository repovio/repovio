> アーカイブされたソース スナップショット。製品ラベルはRepovioを使用します。このリリースのタグ付きデプロイメント ファイルの構成識別子とコンテナー参照を変更せずに使用します。

<a id="access-and-list"></a>

## アクセスとリスト

システム管理者は、**管理 → プロバイダー アカウント**
を開きます。この表には、名前、プロバイダーの種類、ベース URL、有効な状態、および最後の同期が表示されます。タイプ/有効によるフィルタリング、並べ替え、列の変更、およびページ付けを行います。他のロールはプロバイダー アカウントを管理しません。トークンと OAuth シークレットはリスト データでは返されません。

<a id="connect-a-provider"></a>

## プロバイダーに接続する

[**プロバイダーの追加**] を選択し、GitHub、GitLab、Forgejo、または Gitea を選択します。認識可能な名前と正しいインスタンス ベース URL を入力します。 Gitea には 1 つが必要です。 API が設定済みとして報告する認証方法から選択します。一致する OAuth クライアントがない場合は、個人アクセス トークンを使用します。**プロバイダーの確認と追加**
は、保存する前に PAT 資格情報をチェックします。**プロバイダーに接続**
はプロバイダーの同意にリダイレクトし、成功または失敗の通知を返します。

[プロバイダー OAuth セットアップ](/docs/v1.0/provider-oauth)
の読み取りスコープのみを使用します。プロバイダー OAuth はリポジトリ データに接続します。
[OIDC ユーザーのサインイン](/docs/v1.0/authentication)とは別のものです。 Repovio は保存時の資格情報を暗号化し、アップストリーム トークンが書き込みを許可できる場合でも、プロバイダー リソースの変更を提供しません。

<a id="maintain-connections"></a>

## 接続を維持する

参加を制御する行を有効または無効にします。保留中の行アクションは、リクエストが終了する間、競合するアクションをブロックします。無効にすると構成が保持されます。削除はすぐに実行されます。削除アクションを選択する前に、依存する追跡データを考慮してください。現在の画面が公開しないフローを通じてプロバイダーの所有権または資格情報を変更する必要がある場合は、代替接続を作成します。

[リポジトリ](/docs/v1.0/repositories)
とは別にリポジトリを追加します。 Webhook 設定は、プロバイダー アカウントではなく、個々の追跡されるリポジトリに属します。空の検出は、リポジトリがない、不正なインスタンス、不十分な読み取りスコープ、または無効な認証情報を意味する可能性があります。認証オプションの読み込み失敗、検証エラー、OAuth コールバック通知、API エラーを区別します。原因を修正してから再試行してください。進行中の同期エラーがないかジョブを検査します。
