## ব্রাউজ ধরে রাখা রান

খুলুন **ওভারভিউ → ওয়ার্কফ্লো রান → সব রান**। ফলাফলগুলি অ্যাক্সেসযোগ্য সংগ্রহস্থল এবং রক্ষিত ইতিহাসে বিস্তৃত।
সংগ্রহস্থল, প্রদানকারী, স্থিতি, এবং সময়কাল ফিল্টার ব্যবহার করুন (সময়কাল সেকেন্ডে প্রবেশ করানো হয়)। সমস্ত রানের কোন
টেক্সট-সার্চ বক্স নেই; মনোযোগ প্রয়োজন অনুসন্ধান এবং বিস্তারিত তৈরি/শুরু কলাম যোগ করে। কলামগুলি সাজান, দৃশ্যমান কলামগুলি
পরিবর্তন করুন এবং ফলাফলগুলি পৃষ্ঠায় করুন৷ প্রত্যাশিত রান অনুপস্থিত থাকলে ফিল্টারগুলি সাফ করুন।

সারিগুলি কর্মপ্রবাহ এবং সংগ্রহস্থল, প্রদানকারী, স্বাভাবিক অবস্থা, প্রদানকারীর টাইমস্ট্যাম্প এবং সরবরাহের সময়কাল সনাক্ত
করে। সারিবদ্ধ বা অসমাপ্ত রানের সমাপ্তির সময় বা চূড়ান্ত সময়কালের অভাব থাকতে পারে। স্বাভাবিক অবস্থাগুলি হল `queued`,
`running`, `success`, `failed`, `cancelled`, `skipped`, এবং `unknown`। একটি অজানা অবস্থা প্রদানকারী এ চেক করা আবশ্যক.

## একটি রান খুলুন

প্রদানকারীর রান এবং এর লগগুলি খুলতে বাহ্যিক সারি ক্রিয়াটি ব্যবহার করুন৷ Repovio একটি পৃথক সম্পাদনাযোগ্য রান স্ক্রীন
প্রদান করে না, প্রদানকারীর আর্টিফ্যাক্ট ডাউনলোড করে, বা সম্পূর্ণ লগ সিঙ্ক্রোনাইজ করে না। আপনার প্রদানকারী অ্যাকাউন্টের
মাধ্যমে শুধুমাত্র প্রদানকারীর কাছে অনুমোদন, পুনরায় চালান, বাতিল বা প্রেরণ করুন। বর্তমান ব্যর্থতার জন্য
[মনোযোগ প্রয়োজন](/docs/next/needs-attention) ব্যবহার করুন; গেটের জন্য
[অনুমোদনের অপেক্ষায়](/docs/next/awaiting-approval) ব্যবহার করুন।

## হারিয়ে যাওয়া বা বাসি ইতিহাস

একটি খালি টেবিল মানে কোনো রক্ষিত রেকর্ড ফিল্টার এবং আপনার অনুমতির সাথে মেলে না। ধরে রাখা পুরানো রান মুছে ফেলতে পারে।
সংগ্রহস্থল সক্ষমতা, সদস্যপদ, কর্মপ্রবাহের অনুমতি/অস্বীকার প্যাটার্ন এবং [সিঙ্ক্রোনাইজেশন কাজ](/docs/next/guide-jobs) চেক
করুন। একটি পৃষ্ঠা রিফ্রেশ সঞ্চিত ডেটা পুনরায় লোড করে; এটি টেকসই সিঙ্ক্রোনাইজেশন সারি বাইপাস করে না। API পুনরুদ্ধারের
পরে লোড ত্রুটিগুলি পুনরায় চেষ্টা করুন৷
