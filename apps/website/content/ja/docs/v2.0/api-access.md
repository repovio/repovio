## インストールされた API ドキュメント

すべての Repovio API サーバーは、インタラクティブな API ドキュメントを `/docs`
で提供します。ローカル開発では、`http://localhost:3001/docs` を開きます。 REST エンドポイントは、`/api/v1`
ベース パスを使用します。

デプロイメントの場合は、外部からアクセス可能な API オリジンと、リバース プロキシによって構成されたパスを使用します。たとえば、API サーバーが
`https://repovio.example.com` で公開されている場合、そのドキュメントは `https://repovio.example.com/docs`
で公開できます。 Web アプリケーションは、このルートを自動的にプロキシしません。プロキシを公開したい場合は、プロキシを明示的に設定します。
`/api/v1/docs` はドキュメント ルートではありません。

インストールされたリファレンスには、実行中のアプリケーションが記述されています。そのインタラクティブな参照から行われたリクエストはインスタンスを使用し、操作ごとに文書化された認証と権限を必要とします。サインインとアカウントの構成については、[認証](/docs/v2.0/authentication)
を参照してください。 MCP アクセス トークンは、一般的な REST ベアラー トークンとしてではなく、[MCP クライアント](/docs/v2.0/mcp)
を対象としています。

## 静的リリースのリファレンス

この Web サイトの [APIリファレンス](/docs/v2.0/api-reference)
は、選択したリリースの正確なアプリケーション リビジョンから生成された読み取り専用のスナップショットです。 Repovio インスタンスを実行する必要はなく、API リクエストを送信しません。インストールに一致するバージョンを選択してください。インストールされた
`/docs` ページは、実行中のビルドに対して引き続き権限を持ちます。

メソッド、パス、または説明で検索したり、パラメーターと応答スキーマを検査したり、リファレンス ページから完全な OpenAPI
JSON をダウンロードしたりできます。スキーマ識別子と API の説明は、生成されたコントラクトの言語を保持します。
