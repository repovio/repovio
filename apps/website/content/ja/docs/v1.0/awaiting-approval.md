<a id="identify-approval-gates"></a>

## 承認ゲートを特定する

[**ワークフローの実行 → 承認待ち**] を開くと、人間の決定のために一時停止された同期ワークフローが表示されます。ワークフローまたはリポジトリ別に検索し、リポジトリ、プロバイダー、および関連するプル/マージ リクエストのコンテキストを検査します。サイドバーのバッジには、表示される一致する実行が反映されます。メンバーシップ制限はバッジとテーブルの両方に適用されます。

コンテキストとして **Open pull request** を使用するか、**プロバイダーで承認**
を使用してプロバイダー所有のワークフロー ページを開きます。 GitLab 関連する変更をマージ リクエストと呼ぶ場合があります。ワークフローの承認は、コードレビューやマージの承認とは異なります。

<a id="complete-the-provider-action"></a>

## プロバイダーのアクションを完了します

プロバイダー アカウントが承認されている場合は、プロバイダーで認証し、その承認コントロールを使用します。 Repovio 決して承認リクエストを送信しません。 Webhook またはリコンシリエーション読み取りでは、行が消える前に更新されたプロバイダーの状態を監視する必要があります。その後、ストアドキューをリフレッシュします。承認直後に変更されていない行は、同期の遅延を反映している可能性があります。

キューが空であるということは、現在承認が必要な同期実行が表示されていないことを意味します。すべてのリポジトリが接続されていることや、プロバイダー アカウントに承認権限があることを意味するものではありません。ロード失敗時に再試行して検査する
[同期ジョブ](/docs/v1.0/guide-jobs)。
