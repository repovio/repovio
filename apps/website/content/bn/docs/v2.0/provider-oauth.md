এই পৃষ্ঠার PAT/OAuth নির্দেশনায় প্রতি রিপোজিটরির ওয়েবহুক ব্যবহৃত হয়। GitHub App সংযোগে একটি কেন্দ্রীয় ওয়েবহুক থাকে এবং
অ্যাপ ডায়ালগ দিয়ে সেটআপ হয়।

Repovio OAuth বা একটি ব্যক্তিগত অ্যাক্সেস টোকেনের (PAT) মাধ্যমে প্রদানকারীর অ্যাকাউন্টগুলিকে সংযুক্ত করে৷ অন্তত একটি
প্রদানকারী OAuth ক্লায়েন্ট কনফিগার করা হলে OAuth উপলব্ধ। কোন কনফিগার করা OAuth ক্লায়েন্ট ছাড়া, প্রদানকারী-অ্যাকাউন্ট
স্ক্রীন শুধুমাত্র PAT প্রমাণীকরণ অফার করে। Repovio হয় শুধুমাত্র তার রিড-অনলি প্রদানকারী API-এর জন্য ফলাফলের শংসাপত্র
ব্যবহার করে এবং PostgreSQL এ লেখার আগে এটি এনক্রিপ্ট করে।

## OAuth অ্যাপ্লিকেশন নিবন্ধন করুন

Repovio সংযোগ করা উচিত এমন প্রতিটি প্রদানকারী উদাহরণের জন্য একটি OAuth অ্যাপ্লিকেশন নিবন্ধন করুন৷ প্রতিটি অ্যাপ্লিকেশন
রেজিস্ট্রেশনে `OAUTH_CALLBACK_URL` থেকে সঠিক কলব্যাক URL সেট করুন। স্থানীয় ইনস্টলেশনের জন্য ডিফল্ট হল
`http://localhost:3001/api/v1/provider-accounts/oauth/callback`।

API পরিবেশে ক্লায়েন্ট আইডি এবং ক্লায়েন্ট সিক্রেট কনফিগার করুন, কখনই ওয়েব অ্যাপ্লিকেশন বা গিটে নয়:

```dotenv
OAUTH_CALLBACK_URL=https://repovio.example.com/api/v1/provider-accounts/oauth/callback
GITHUB_OAUTH_CLIENT_ID=...
GITHUB_OAUTH_CLIENT_SECRET=...
GITLAB_OAUTH_BASE_URL=https://gitlab.example.com
GITLAB_OAUTH_CLIENT_ID=...
GITLAB_OAUTH_CLIENT_SECRET=...
FORGEJO_OAUTH_BASE_URL=https://forgejo.example.com
FORGEJO_OAUTH_CLIENT_ID=...
FORGEJO_OAUTH_CLIENT_SECRET=...
```

এই ইনস্টলেশনের প্রয়োজন শুধুমাত্র প্রদানকারী কনফিগার করুন। ক্লায়েন্ট আইডি এবং গোপনীয়তা সবসময় জোড়া হিসাবে কনফিগার করা
আবশ্যক. `GITLAB_OAUTH_BASE_URL` ইনস্টল করা OAuth অ্যাপ্লিকেশনের জন্য একক GitLab দৃষ্টান্ত সনাক্ত করে৷ Forgejo এর OAuth
ক্লায়েন্ট কনফিগার করা হলে একটি সুস্পষ্ট ভিত্তি URL প্রয়োজন৷

## সুযোগ পড়ুন

অ্যাপ্লিকেশন নিবন্ধন করার সময় এই সুযোগগুলি ব্যবহার করুন:

- GitHub: `repo security_events`। Repovio নিরাপত্তা সতর্কতা পড়তে পারে তার আগে বিদ্যমান OAuth অ্যাকাউন্টগুলিকে অবশ্যই
  পুনরায় অনুমোদন করতে হবে৷
- GitLab: `read_api read_user`।

সূক্ষ্ম-দানাযুক্ত GitHub ব্যক্তিগত অ্যাক্সেস টোকেনগুলির জন্য Dependabot সতর্কতা, কোড স্ক্যানিং সতর্কতা, এবং গোপন
স্ক্যানিং সতর্কতাগুলি পড়ার অ্যাক্সেস প্রয়োজন। GitLab নিরাপত্তা সতর্কতা অ্যাক্সেস অতিরিক্তভাবে ইনস্ট্যান্স লাইসেন্স এবং
টোকেন মালিকের প্রকল্প ভূমিকার উপর নির্ভর করে; অনুপলব্ধ সতর্কতা প্রকারগুলি অন্যান্য সংগ্রহস্থল সিঙ্ক্রোনাইজেশন স্কোপগুলি
ব্যর্থ না করে দেখানো হয়।

- Forgejo: `read:repository`।
- Gitea: ইনস্ট্যান্স বেস URL সহ Gitea প্রদানকারী-অ্যাকাউন্ট ফর্মে পঠিত অ্যাক্সেস সহ একটি ব্যক্তিগত অ্যাক্সেস টোকেন
  কনফিগার করুন। Repovio বর্তমানে একটি শেয়ার করা Gitea OAuth ক্লায়েন্ট অফার করে না কারণ প্রতিটি স্ব-হোস্ট করা উদাহরণের
  নিজস্ব অ্যাপ্লিকেশন নিবন্ধন প্রয়োজন।

Repovio এর অ্যাডাপ্টারগুলি শুধুমাত্র বৈধতা, আবিষ্কার, ওয়ার্কফ্লো সিঙ্ক্রোনাইজেশন, এবং ওয়েবহুক যাচাইকরণকে প্রকাশ করে৷
তারা প্রদানকারী সংস্থান তৈরি, আপডেট, প্রেরণ, পুনরায় চালায়, বাতিল বা মুছে দেয় না। OAuth ক্লায়েন্টের গোপনীয়তা API
পরিবেশে থাকে এবং প্রদানকারীর টোকেন Repovio API দ্বারা কখনই ফেরত দেওয়া হয় না।
