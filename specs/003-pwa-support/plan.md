## Summary

Keep the existing `@vite-pwa/nuxt` architecture. First reproduce installation, update, routing, and cache behavior using
production builds. Add missing regression coverage, fix only reproduced gaps, and document platform limitations. This is
not a new PWA implementation. [Research](research.md) records decisions; [contracts](contracts/pwa.md) define acceptance.

## Technical Context

**Language/Version**: TypeScript/Vue, Node.js 26.13.0, pnpm 11.28.9; preserve compiler aliases and version ranges.

**Primary Dependencies**: Nuxt `^4.6.3`, `@vite-pwa/nuxt` `^1.1.1`, Workbox through the existing dependency graph,
Nuxt UI, i18n, Playwright `^1.64.1`, and Vitest `^5.0.5`.

**Storage**: Existing browser Cache Storage for public static build assets only; no database or schema changes.

**Testing**: Production Playwright PWA suite, focused web unit tests, device checks, and existing repository checks.

**Target Platform**: HTTPS deployment or localhost; desktop/Android Chromium and iOS Safari with capability differences.

**Project Type**: Nuxt 4 SPA with Nitro runtime branding routes in a pnpm/Nx monorepo.

**Performance Goals**: No new polling, network background jobs, runtime caching, or forced startup dependencies. Installed
online launch and update behavior must remain comparable to the baseline; inspect request traces for added work.

**Constraints**: API and authentication responses never cached by the service worker; no offline application startup
promise; preserve manifest identity and runtime branding; normal online use survives unavailable PWA capabilities.

**Scale/Scope**: Web application only; existing installation/update/cache boundaries and their tests/documentation.

## Phase 0: Research Outcome

Existing PWA plumbing already meets the architectural baseline. Coverage proves Chromium manifest/installability and a
successful update cycle, but does not establish failure recovery, authenticated cache isolation, real-device
installation, or standalone OIDC behavior. These are evidence gaps, not confirmed application defects.

## Phase 1: Design and Verification Order

1. Establish baseline with the existing production suite; record manifest, headers, worker state and cache contents.
2. Extend tests for authenticated cache exclusion, logout/account switch, registration failure, update rejection/retry,
   dismissal, multiple tabs, and a second update cycle. Isolate mutation of built `sw.js` and restore it after failures.
3. Fix reproduced defects at the existing config/component boundary. Preserve the manual update model and no-cache
   policy. Treat unavailable install controls as capability differences rather than failures.
4. Validate standalone sign-in, navigation and installation on the documented device matrix. Update English documentation
   and affected application locale files. Record unavailable devices without claiming their behavior verified.
5. Run affected checks and review evidence against every requirement before any completion claim.
