> محفوظ شدہ ماخذ سنیپ شاٹ۔ پروڈکٹ لیبلز Repovio استعمال کرتے ہیں۔ اس ریلیز کی ٹیگ شدہ تعیناتی فائلوں سے کنفیگریشن شناخت
> کنندگان اور کنٹینر حوالہ جات کو بغیر تبدیلی کے استعمال کریں۔

<a id="review-accounts"></a>

## اکاؤنٹس کا جائزہ لیں۔

سسٹم کے منتظمین **ایڈمنسٹریشن → صارفین** کھولتے ہیں۔ جدول صارف نام، اوتار/ڈسپلے کا نام، کردار، مقامی/OIDC اصل، اور تخلیق
شدہ/اپ ڈیٹ کردہ ٹائم سٹیمپ دکھاتا ہے۔ کردار کے لحاظ سے فلٹر کریں، ترتیب دیں، کالم تبدیل کریں، یا صفحہ بندی کریں۔ ناظر یا
مینیجر کے لیے مخزن تک رسائی کے لیے علیحدہ [مخزن کی رکنیت](/docs/v1.0/repositories) کی ضرورت ہوتی ہے۔ شناخت فراہم کرنے
والے گروپ وہ رکنیت نہیں بناتے ہیں۔

<a id="provisioning-and-deletion"></a>

## فراہمی اور حذف کرنا

صارفین کے صفحہ میں کوئی تخلیق صارف یا ترمیم صارف فارم نہیں ہے۔ اضافی مقامی صارفین صارف نام، پاس ورڈ اور کردار کا استعمال
کرتے ہوئے صرف منتظم کے لیے محفوظ صارف API کے ذریعے بنائے جاتے ہیں۔ OIDC صارفین کو کنفیگر شدہ شناختی لاگ ان کے ذریعے
فراہم کیا جاتا ہے۔ نقشہ سازی اور اکاؤنٹ کی علیحدگی کے لیے [تصدیق](/docs/v1.0/authentication) دیکھیں۔ اپنے ترتیبات کے
صفحہ پر قابل تدوین پروفائل کی موجودگی سے صارف کی ترمیم کی کارروائی کا اندازہ نہ لگائیں۔

ڈیلیٹ ایکشن دوسرے صارفین کے لیے دستیاب ہے اور فوری طور پر عمل میں لایا جاتا ہے۔ اکاؤنٹ کو منتخب کرنے سے پہلے اس کا جائزہ
لیں۔ آپ اس API یا اسکرین کے ذریعے اپنا اکاؤنٹ حذف نہیں کر سکتے۔ Repovio صارف کو حذف کرنے سے مقامی رسائی ختم ہوجاتی ہے۔
یہ GitHub، GitLab، Forgejo، یا Gitea پر کسی بھی فراہم کنندہ کے اکاؤنٹ کو حذف نہیں کرتا ہے۔ حذف کرنے سے پہلے متاثرہ صارف
کی رسائی کا جائزہ لیں۔

<a id="user-mcp-tokens"></a>

## صارف MCP ٹوکنز

ٹوکن میٹا ڈیٹا کی فہرست بنانے یا تصدیق کے ساتھ ٹوکن منسوخ کرنے کے لیے صارف کا MCP-ٹوکن ڈائیلاگ کھولیں۔ منتظمین اس
ڈائیلاگ کے ذریعے سادہ متن کے ٹوکن کی قدروں کو بازیافت نہیں کرسکتے ہیں یا کسی دوسرے صارف کا ٹوکن نہیں بنا سکتے ہیں۔
صارفین [MCP ترتیبات](/docs/v1.0/mcp) میں اپنے ٹوکن بناتے ہیں۔ خالی فہرستیں اور لوڈ کی غلطیاں الگ الگ ہیں۔ API ریکوری کے
بعد دوبارہ کوشش کریں۔ سپورٹ رپورٹس یا اسکرین شاٹس میں کبھی بھی ٹوکن ویلیو کاپی نہ کریں۔

<a id="local-user-api"></a>

## API کے ذریعے مقامی صارف فراہم کریں۔

ایڈمنسٹریٹر بیئرر تصدیق اور `Content-Type: application/json` کے ساتھ `POST /api/v1/users` بھیجنے کے لیے HTTPS پر API
کلائنٹ کا استعمال کریں۔ کلائنٹ کے محفوظ ان پٹس میں پلیس ہولڈرز کو تبدیل کرتے ہوئے اس درخواست کی باڈی فراہم کریں:

```json
{
  "username": "new-user",
  "password": "REPLACE_WITH_A_PASSWORD_OF_AT_LEAST_12_CHARACTERS",
  "role": "VIEWER"
}
```

درست کردار `VIEWER`، `MANAGER`، اور `SYSTEM_ADMIN` ہیں۔ صرف مطلوبہ کردار تفویض کریں، پھر مخزن کی رکنیت الگ سے دیں۔ جواب
میں محفوظ صارف میٹا ڈیٹا ہے، پاس ورڈ یا اس کا ہیش نہیں۔ دوبارہ کوشش کرنے سے پہلے ایک ڈپلیکیٹ صارف نام یا غلط درخواست کو
درست کرنا ضروری ہے۔ ٹریک شدہ فائلوں، شیل ہسٹری، اسکرین شاٹس، یا ایشو رپورٹس میں پاس ورڈز یا بیئرر ٹوکن اسٹور نہ کریں۔
