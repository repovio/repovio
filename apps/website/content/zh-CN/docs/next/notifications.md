<a id="access-and-channel-list"></a>

## 访问和频道列表

打开**操作→通知→渠道**。通道是全局 Repovio 配置，而不是存储库拥有的管理器配置。系统管理员创建、编辑、测试、启用/禁用和删除通道。存储库管理员状态不授予通道管理权限。该表显示名称、类型、安全目的地元数据、订阅事件、启用状态和更新时间；使用类型/启用的过滤器、排序、列控件和分页。

<a id="create-a-destination"></a>

## 创建目的地

创建和编辑对话框包含四个步骤：**名称和类型**、**目标**、**事件**和**预览和检查**。设置名称、类型和启用状态，配置目标，
选择事件订阅和筛选条件，然后检查摘要及可选的工作流预览，最后保存。上一步和下一步会保留草稿。
检查页面隐藏目标凭据。

选择 **添加通道**，输入名称，选择类型，然后配置目标：

- **电子邮件：** SMTP 主机/端口、传输安全、发件人、可选身份验证和收件人。
- **Gotify：** 服务器 URL、应用程序令牌和优先级。
- **ntfy：** 服务器、主题、可选身份验证/令牌和优先级。
- **Discord：** Webhook 目标。
- **自定义 Apprise URL：** 支持的 Apprise 服务 URL。
- **浏览器推送：**接收用户；每个收件人必须启用 [他们的设备](/docs/next/browser-push)。

在同一对话框中配置
[事件订阅和预览](/docs/next/notification-rules)。保存并等待请求后再关闭。验证或保存失败会使表单可供更正。

<a id="edit-test-and-remove"></a>

## 编辑、测试和删除

目的地在静态时被加密。您可以保存它，但无法读回它。除非选择
**替换目标配置**，否则编辑会保留其存储的凭据。通道类型不可更改；相反，创建一个新频道。标记为**需要重新配置**
的迁移通道在其目标被替换之前无法重新启用。浏览器推送通道使用用户订阅并拒绝传输目的地机密。

使用行测试操作将真实通知发送到配置的目的地；它不会修改提供者数据。查看 [通知发送历史](/docs/next/notification-history)
中的结果。禁用频道以暂停传送，或在不再需要时将其删除。删除立即执行。切勿将凭据粘贴到屏幕截图或支持报告中。

电子邮件、Gotify、ntfy、Discord 和自定义目标使用 API 的捆绑 Apprise
CLI；不需要单独的 Apprise 服务器。如果请求失败，请在 API 恢复后重试。空列表意味着没有可见的配置通道匹配过滤器；清除过滤器或创建通道。交付失败详细信息仅包含已清理的错误。
