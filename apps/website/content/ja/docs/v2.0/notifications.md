<a id="access-and-channel-list"></a>

## アクセスとチャンネルリスト

**[操作] → [通知] → [チャンネル]**
を開きます。チャネルはグローバル Repovio 構成であり、リポジトリ所有のマネージャー構成ではありません。システム管理者は、チャネルの作成、編集、テスト、有効化/無効化、および削除を行います。リポジトリ マネージャ ステータスではチャネル管理は許可されません。この表には、名前、タイプ、安全な宛先メタデータ、サブスクライブされたイベント、有効な状態、および更新時間が表示されます。タイプ/有効フィルター、並べ替え、列コントロール、およびページネーションを使用します。

<a id="create-a-destination"></a>

## 宛先を作成する

[**チャンネルの追加**] を選択し、名前を入力し、タイプを選択して、宛先を構成します。

- **電子メール:** SMTP ホスト/ポート、トランスポート セキュリティ、送信者、オプションの認証、および受信者。
- **Gotify:** サーバー URL、アプリケーション トークン、および優先度。
- **ntfy:** サーバー、トピック、オプションの認証/トークン、および優先度。
- **Discord:** Webhook 宛先。
- **カスタム Apprise URL:** サポートされている Apprise サービス URL。
- **ブラウザ プッシュ:** 受信ユーザー。各受信者は [彼らのデバイス](/docs/v2.0/browser-push) を有効にする必要があります。

同じダイアログで [イベントのサブスクリプションとプレビュー](/docs/v2.0/notification-rules)
を設定します。保存してリクエストを待ってから閉じます。検証または保存に失敗した場合、フォームは修正可能な状態のままになります。

<a id="edit-test-and-remove"></a>

## 編集、テスト、削除

宛先は保存時に暗号化されます。保存はできますが、読み返すことはできません。 [**宛先構成を置き換える**] が選択されていない限り、編集では保存された資格情報が保持されます。チャネルタイプは変更できません。代わりに新しいチャンネルを作成してください。**再構成が必要**
とマークされた移行されたチャネルは、宛先が置き換えられるまで再度有効にすることはできません。ブラウザ プッシュ チャネルはユーザー サブスクリプションを使用し、トランスポート宛先シークレットを拒否します。

行テスト アクションを使用して、構成された宛先に実際の通知を送信します。プロバイダーのデータは変更されません。
[配信履歴](/docs/v2.0/notification-history)
で結果を確認します。チャネルを無効にして配信を一時停止するか、不要になったらチャネルを削除します。削除はすぐに実行されます。認証情報をスクリーンショットやサポート レポートに貼り付けないでください。

電子メール、Gotify、ntfy、Discord、およびカスタム宛先は、API にバンドルされている Apprise
CLI を使用します。別の Apprise サーバーは必要ありません。リクエストが失敗した場合は、API 回復後に再試行してください。空のリストは、フィルターに一致する設定済みチャネルが表示されていないことを意味します。フィルターをクリアするか、チャンネルを作成してください。配信失敗の詳細には、サニタイズされたエラーのみが含まれます。
