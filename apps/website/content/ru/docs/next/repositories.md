<a id="browse-and-open-details"></a>

## Просматривайте и открывайте детали

Откройте репозиторий из таблицы для перехода между обзором, запусками рабочих процессов, задачами, запросами на
слияние, предупреждениями безопасности и настройками. Страницы активности ограничены этим репозиторием и поддерживают
фильтры, сортировку, пагинацию и переход по строке. Для предупреждений нужны права управления; настройки доступны
только системным администраторам. Ссылка провайдера открывает внешний репозиторий.

Обзор показывает общие сведения, сроки хранения, последнюю синхронизацию, возраст данных, интервал, текущее задание и
недавнюю активность. Ожидающие и выполняемые задания показывают прогресс и безопасно классифицированные ошибки.

<a id="add-and-maintain-tracking"></a>

## Добавление и поддержание отслеживания

Репозитории добавляют только системные администраторы. Выберите включенную учетную запись поставщика, дождитесь
обнаружения и выберите один или несколько неотслеживаемых репозиториев. Уже отслеживаемые репозитории исключаются. Если
часть множественного добавления завершается неудачей, успешные выборки остаются добавленными, и для повторной попытки
остаются только неудачные выборки. Пустой список провайдеров требует сначала подключения включенного
[учетная запись провайдера](/docs/next/provider-accounts).

Администраторы могут включать/отключать отслеживание, **обновлять данные поставщика** и ставить в очередь синхронизацию
только для чтения. Идентификация репозитория использует учетную запись поставщика и идентификатор стабильного
репозитория поставщика. При переименованиях/переносах сохраняется история, фильтры, членство и каналы; Обновление
метаданных отклоняет другой идентификатор по старому пути, а не переназначает его. Отключенные репозитории сохраняют
сохраненные данные, но перестают участвовать в синхронизации.

<a id="repository-settings-sections"></a>

## Разделы настроек репозитория

Настройки репозитория содержат пять дополнительных вкладок. Каждый раздел использует доступную ширину; на узких экранах поля располагаются вертикально. Ссылки можно передавать другим пользователям и восстанавливать после перезагрузки или переходов Назад/Вперёд. По умолчанию открыт раздел «Общие».

| Раздел                    | Назначение                            | Адрес                        |
| ------------------------- | ------------------------------------- | ---------------------------- |
| Общие                     | Сроки хранения                        | `/repositories/:id/settings` |
| Webhook                   | Настройка вебхука репозитория         | `?tab=webhook`               |
| Фильтры рабочих процессов | Разрешающие и запрещающие шаблоны     | `?tab=workflow-filters`      |
| Участники                 | Прямой доступ пользователей и роли    | `?tab=members`               |
| Доступ групп              | Дополнительный доступ локальных групп | `?tab=groups`                |

Несохранённые значения и незавершённые запросы сохраняются при переключении вкладок в течение одного посещения настроек. Выход из настроек или открытие другого репозитория удаляет черновики, включая созданные секреты вебхуков. Для сохранения используйте действие сохранения или назначения в соответствующем разделе.

Диалог быстрых сведений удалён. Старые ссылки `?repository=` открывают обзор. Полные страницы сохраняют обновление, синхронизацию, ссылки провайдера и локальное удаление. Изменение URL не предоставляет наблюдателям или менеджерам доступ к настройкам.

<a id="retention-filters-and-memberships"></a>

## Хранение, фильтры и членство

Администраторы устанавливают отдельные переопределения срока хранения рабочих процессов, задач и запросов на включение,
каждый от 1 до 3650 дней. Пустое значение восстанавливает соответствующий
[система по умолчанию](/docs/next/settings-system). Фильтры рабочих процессов принимают шаблоны **ALLOW** и**DENY**;
отрицание имеет приоритет. Добавьте непустые шаблоны или удалите существующие. Ограничительные фильтры могут объяснить
отсутствие запусков.

В членстве добавьте пользователя, не являющегося администратором, в качестве наблюдателя или менеджера, измените его
роль репозитория или закройте доступ. Администраторы исключены из выбора участников, поскольку у них уже есть
неограниченный доступ. Глобальному менеджеру по-прежнему необходимо членство в менеджере для использования возможностей
управления репозиторием, таких как оповещения системы безопасности.

<a id="webhooks-and-failures"></a>

## Вебхуки и сбои

На карточке веб-перехватчика репозитория отображается URL-адрес обратного вызова, настроенное состояние, инструкции
поставщика и последняя доставка. Он может генерировать/копировать секрет, сохранять конфигурацию, выполнять ротацию с
явным подтверждением или удалять конфигурацию. Отсутствующий общедоступный URL-адрес необходимо исправить до регистрации
поставщика. Секреты отображаются только во время настройки; держите их в секретном менеджере. Следуйте
[Веб-перехватчики репозитория](/docs/next/provider-webhooks) для настройки и проверки.

Наблюдатели и менеджеры просматривают метаданные только для чтения в обзоре; настройки доступны лишь администраторам. Повторяйте запросы после устранения причины и проверяйте [Задания](/docs/next/guide-jobs) при сбоях синхронизации.

<a id="local-user-and-group-management"></a>

## Локальные группы доступа

В разделе группового доступа репозитория назначьте Viewer или Manager, измените или удалите право. Прямые и групповые
права объединяются, Manager сильнее. Управление требует глобальной роли Manager; системные администраторы не ограничены.
Отзыв действует со следующего запроса, если нет другого права. Группы работают с локальными и OIDC-записями, без
синхронизации OIDC claims.

[Локальные группы доступа](/docs/next/users#local-access-groups)

<a id="delete-local-tracking"></a>

## Удаление локального отслеживания

Системные администраторы могут выбрать **Удалить репозиторий** на странице сведений. Подтверждение
содержит имя репозитория и объясняет безвозвратное удаление локальных рабочих процессов, запусков, issues, pull requests,
предупреждений безопасности, настроек, прав доступа, истории вебхуков, состояния синхронизации и связанных уведомлений.
Учетная запись провайдера и данные репозитория у провайдера остаются без изменений.

Удаление заблокировано во время синхронизации; дождитесь завершения и повторите попытку. Ожидающие запросы синхронизации
удаляются вместе с репозиторием. Из подписок на уведомления удаляется фильтр этого репозитория; подписка только на него
удаляется, а не становится глобальной. Общие каналы сохраняются.

Репозиторий можно снова добавить через существующий выбор провайдера. Отслеживание начинается заново без восстановления
прежней локальной истории или настроек.
