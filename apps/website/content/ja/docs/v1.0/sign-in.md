> アーカイブされたソース スナップショット。製品ラベルはRepovioを使用します。このリリースのタグ付きデプロイメント ファイルの構成識別子とコンテナー参照を変更せずに使用します。

<a id="local-sign-in"></a>

## ローカルサインイン

`/auth/signin`
を開き、ローカル ユーザー名とパスワードを入力し、**サインイン**を選択します。認証が完了するまで待ちます。認証情報が拒否された場合は、フォームに残されたままになります。ユーザー名を確認し、導入オペレーターに
[パスワードの回復](/docs/v1.0/authentication#reset-a-forgotten-password)
について問い合わせてください。 Repovio には電子メールのパスワード リセット フローがありません。

新しいインストールでは、代わりに [初回実行時のセットアップ](/docs/v1.0/setup)
が開きます。認証されると、ナビゲーションと結果はロールとリポジトリ メンバーシップに応じて異なります。ダッシュボードが空であっても、サインインが失敗したわけではありません。

<a id="openid-connect"></a>

## OpenID Connect

管理者が OIDC を有効にする場合は、追加のプロバイダーのサインイン ボタンを使用します。 ID プロバイダーの独自のページで認証を完了し、コールバックを終了させます。拒否されたグループ マッピング、期限切れのトランザクション、またはプロバイダーの障害によりエラーが返されます。新しいサインインの試行を開始します。 OIDC は、電子メールを照合して既存のローカル アカウントをリンクすることはありません。

OIDC ログインは、プロバイダー OAuth 接続とは別のものです。 Repovio ユーザーを認証します。 GitHub、GitLab、Forgejo、または Gitea リポジトリには接続しません。 ID で管理される名前とパスワードは、ID プロバイダーで変更する必要があります。

<a id="sign-out"></a>

## サインアウト

ユーザーメニューからサインアウトを選択します。サインアウトすると、リポジトリの削除、プロバイダーの資格情報の変更、プロバイダー リソースの変更を行わずに、ブラウザー セッションが削除されます。共有デバイスでは、終了したらサインアウトします。 API セッションの有効期限が切れた場合は、失敗したアクションを再試行する前に、再度サインインしてください。 OIDC が有効な場合、ローカル パスワード サインインは引き続き利用可能です。
